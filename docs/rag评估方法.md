# RAG 系统评估 · 工程实践版（可直接落地）

## 一、整体思路（项目里必须遵守）
1. **先评估检索，再评估生成**
   检索不行，生成再好也没用；检索好，生成才可控。
2. **离线评估 + 线上 AB 实验 + 人工抽检**三层闭环
3. **指标必须可自动化计算**，不能只靠人主观打分

# 二、文档导入流水线评估（前置质量关卡）
所有导入知识库的文档必须先通过以下评估，否则不能进入检索环节：
## 1. 文档解析质量
### （1）OCR识别准确率
- 含义：扫描版PDF/图片格式文档的文字识别准确率
- 落地标准：≥ 98%
### （2）格式解析正确率
- 含义：Word/Excel/PDF等格式文档的结构、表格、列表解析正确性
- 落地标准：≥ 99%

## 2. 分块质量
### （1）语义分块准确率
- 含义：语义感知分块的完整性、断点合理性
- 落地标准：≥ 95% 分块无语义断裂
### （2）父子分块关联正确率
- 含义：父子分层分块的关联关系正确性
- 落地标准：100% 正确关联

## 3. 元数据提取质量
### （1）领域标签提取准确率
- 含义：发展领域、脑区等标签提取正确性
- 落地标准：≥ 98%
### （2）年龄范围提取准确率
- 含义：目标年龄范围提取正确性
- 落地标准：100%
### （3）关键词提取准确率
- 含义：主题关键词提取相关性
- 落地标准：≥ 95%

## 4. 索引构建质量
### （1）向量入库准确率
- 含义：向量生成与入库的一致性
- 落地标准：100% 无空向量、错向量
### （2）元数据关联正确率
- 含义：chunk与对应元数据的关联正确性
- 落地标准：100%

# 三、检索模块评估（最关键）
## 1. 必须统计的核心指标（项目必接）
### （1）召回率 Recall@k
- 含义：知识库中**真正相关的 chunk** 被检索出来的比例
- 项目用法：
  - 构造一批**标注好的问答对**（问题 → 应该命中哪些 chunk、对应年龄范围、发展领域）
  - 计算 `Recall@1/3/5/10`
- 落地标准：
  - 业务优先保证 **Recall@3 ≥ 90%**，儿童发展评估场景高风险零容忍漏信息

### （2）精确率 Precision@k
- 含义：返回的 k 条里**真正相关**的比例
- 落地标准：
  - **Precision@3 ≥ 75%** 否则上下文噪声太大，LLM 容易乱编

### （3）MRR（Mean Reciprocal Rank）
- 含义：**第一个正确答案的位置倒数均值**
- 项目意义：用户只看前 1～2 条，MRR 低 = 体验差
- 落地标准：**MRR ≥ 0.7** 基本可用

### （4）上下文相关性（Context Relevance）
- 用 LLM 打分：检索内容里**真正能用来回答问题**的比例
- 输出 1～5 分
- 落地标准：平均分 ≥ 4.3 合格

### （5）元数据过滤准确率
- 含义：检索结果与问题对应的年龄范围、发展领域标签的匹配准确率
- 项目意义：儿童发展评估必须严格匹配年龄阶段，错误的年龄信息会造成严重误导
- 落地标准：**100% 匹配**，零容忍错误

## 2. 检索扩展指标（本项目特有）
### （1）查询预处理准确率
- 含义：查询重写、同义词扩展的准确性
- 落地标准：≥ 95%

### （2）混合检索权重合理性
- 含义：BM25稀疏检索与向量语义检索的权重配比效果
- 评估方式：对比不同权重组合下的Recall/Precision指标
- 目标：找到最优权重配比

### （3）重排序提升率
- 含义：bge-reranker-v2-m3重排序后MRR/Recall指标提升幅度
- 落地标准：≥ 15% 提升

### （4）去重逻辑有效性
- 含义：三级去重策略的误判率、漏判率
- 落地标准：误判率 ≤ 1%，漏判率 ≤ 0.5%

---

## 2. 检索常见问题定位（项目排查表）
- Recall 低 → 向量模型不行 / chunk 切割不对 / 知识库不全
- Precision 低 → 相似度阈值太低 / 停用词没处理 / 领域泛文本太多
- MRR 低 → 重排序模型（Reranker）没加 / 权重不合理
- 关键词场景失效 → 纯向量不行，必须**混合稀疏检索（BM25）**

# 三、生成模块评估（工程可自动化）
## 1. 三大核心指标（必须接入）
### （1）忠实度 Faithfulness
- 定义：答案中**不幻觉、能被上下文支持**的陈述占比
- 自动化方式：LLM 判断每一句话是否被上下文支撑
- 落地标准：**≥ 98%** 儿童发展评估领域零容忍幻觉，否则不能上线

### （2）回答相关性 Answer Relevance
- 定义：是否切题、不跑偏、不废话
- LLM 1～5 分
- 落地标准：≥ 4.5 分

### （3）完整性 Completeness
- 定义：是否覆盖问题所有要点
- 适合客服、知识库、法规类场景
- 落地标准：≥ 90% 要点覆盖

## 2. 儿童发展领域特有指标（必须接入）
### （1）专业术语准确率
- 定义：发展心理学、儿童教育相关专业术语使用的正确率
- 自动化方式：领域术语库匹配 + LLM校验
- 落地标准：**≥ 99%**

### （2）年龄适配性
- 定义：回答内容是否符合对应年龄段儿童的发展特点，没有超前或滞后建议
- LLM 1～5 分
- 落地标准：≥ 4.8 分

### （3）发展建议科学性
- 定义：给出的发展建议是否符合儿童发展科学研究结论，无错误引导
- LLM 1～5 分 + 专家抽检
- 落地标准：≥ 4.8 分

---

## 2. 可直接用的 LLM 评估 Prompt（复制即用）
### 忠实度评估
```
你需要评估回答是否完全基于上下文，没有编造信息。
上下文：{context}
问题：{query}
回答：{answer}
请输出：
1. 忠实度分数（1-5）
2. 编造内容（若无则写无）
```

### 相关性评估
```
问题：{query}
回答：{answer}
评估回答是否切题、是否完整、是否冗余。
输出 1-5 分，并简要说明。
```

# 六、项目落地流程（儿童发展评估定制版）
## 阶段 1：构建领域专用测试集（2 天完成）
- 收集真实儿童发展评估相关问题 ≥ 300 条，覆盖各年龄段和发展领域
- 人工标注维度：
  - 问题 → 应该命中哪些 chunk
  - 问题 → 对应年龄范围、发展领域标签
  - 问题 → 标准答案要点
  - 问题 → 专业术语校验标准
  - 问题 → 年龄适配性要求

## 阶段 2：文档导入流水线评估（半天）
- 跑文档解析、分块、元数据提取、索引构建全流程指标
- 输出导入质量报告，修复不合格的文档处理逻辑

## 阶段 3：跑检索指标（半天）
- 计算 Recall@1/3/5、Precision@1/3/5、MRR
- 计算元数据过滤准确率、查询预处理准确率
- 计算重排序提升率、去重逻辑有效性
- 输出检索错误案例：漏召回 / 错召回 / 元数据匹配错误

## 阶段 4：优化检索（1～3 天）
- 优化语义分块策略、父子分块参数
- 优化BM25 + 向量混合检索权重配比
- 优化查询重写、同义词扩展规则
- 调整Reranker阈值、年龄过滤逻辑
- 优化去重策略参数

## 阶段 5：生成效果自动化评估（接入脚本）
- 批量跑 Faithfulness / Relevance / Completeness
- 批量跑专业术语准确率、年龄适配性、发展建议科学性
- 统计幻觉率、答非所问率、专业错误率
- 输出 Bad Case 清单，按错误类型分类

## 阶段 6：线上监控
- 埋点：
  - 检索召回数量、元数据过滤准确率
  - 专业术语错误率、年龄适配错误率
  - 用户“不满意”点击、重复提问率
  - LLM 生成长度、耗时
  - 缓存命中率
- 每周跑一次全量离线评估，防止版本退化
- 每月开展一次专家抽检，重点审核发展建议科学性
