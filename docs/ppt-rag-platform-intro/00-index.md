## 一、这是什么

这是一套完整的 RAG 平台化改造 PPT 内容素材库，共 10 个主题文件。素材库回答一条主线问题链：

```
纯 LLM 有幻觉，为什么需要 RAG？
    → MVP 怎么做（4 个核心模块）？
        → MVP 为什么不够（5 大局限）？
            → 平台化怎么做（8 大目标 + 6 项核心能力）？
                → 值得做吗（成本 + 技术 + 对比）？
```

每个文件以**一个核心问题**开篇，全文围绕回答这个问题展开。不讲代码细节，只讲「解决了什么问题」「为什么这样解决」「怎么做（原理 + 参数 + 量化数据）」。

### 评估指标速查

| 指标 | 一句话 | 好分数 | 差分数 |
|------|--------|--------|--------|
| Precision@K | 返回的结果中有多少是对的 | > 0.75 | < 0.5 |
| Recall | 相关的文档有多少被找到了 | > 0.70 | < 0.4 |
| MRR | 第一个有用结果排在第几位 | > 0.8 | < 0.3 |
| NDCG@K | 相关文档是否排在前面 | > 0.8 | < 0.5 |
| Faithfulness | 答案中有多少有上下文依据 | > 0.85 | < 0.6 |
| AnswerRelevancy | 答案是否回答了问题 | > 0.8 | < 0.5 |
| Groundedness | 整体论点是否有支撑 | > 0.8 | < 0.5 |

## 五、写作约定

每个文件遵循统一的结构范式：

1. **开篇抛核心问题**（前两段内必须出现）— "如果不解决，会怎样？"
2. **展开回答** — 从「为什么需要」到「怎么做（原理 + 参数 + 正反例 + 量化数据）」
3. **末尾收束** — 关键设计点总结表 + 一句话总结
4. **跨文件引用** — 不重复原理，标注"详见 0X-xxx.md"

概念讲解的深度标准：不仅说"XX 参数控制 YY"，还要说"XX 设为 A 时会发生什么，设为 B 时会发生什么，默认值 C 的依据是什么，什么场景下应该偏离默认值"。
