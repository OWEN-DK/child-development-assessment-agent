## 一、设计目标

重构系统配置页面，解决现有布局畸变、信息层级混乱、功能可理解性差等问题，提供双模式配置体验：
- **专家模式**：侧边栏 + 手风琴 + 搜索优先 + LLM健康度诊断，适合熟悉系统的用户快速操作
- **向导模式**：分步引导配置，每步聚焦一个主题，提供推荐配置，适合新手或首次配置

两种模式共享同一份配置数据草稿，切换模式不丢失未保存修改。

### 2.2 数据流

```
ConfigStore (Zustand)
├── configFields: ConfigFieldMetadata[]  // 配置元数据
├── draftChanges: Record<string, any>    // 未保存修改
├── activeVersion: string | null         // 当前版本
├── modePreference: 'expert' | 'wizard'  // 用户偏好模式
├── healthDiagnostic: DiagnosticResult   // LLM诊断结果
└── searchQuery: string                  // 搜索关键词

Actions:
├── loadConfig()                         // 加载配置
├── updateDraft(key, value)              // 更新草稿
├── saveConfig(description)              // 保存配置
├── undoChange(key)                      // 撤销单个修改
├── switchMode(mode)                     // 切换模式
├── runHealthDiagnostic()                // 运行健康诊断
└── setSearchQuery(query)                // 设置搜索关键词
```

### 3.2 核心功能

| 功能 | 说明 |
|------|------|
| 侧边栏导航 | 5大配置分类，显示状态图标，点击平滑滚动到对应区域 |
| 搜索功能 | 支持⌘K快捷键，按名称/描述/分类模糊匹配，结果高亮 |
| 状态筛选 | 按生效中/需重启/有错误筛选配置项 |
| 手风琴折叠 | 配置分类可展开/收起，避免页面过长 |
| 修改标记 | 已修改配置项高亮显示，展示"原值→新值"对比 |
| 单个撤销 | 每个修改项旁边有撤销按钮，支持单个撤销 |
| 收藏功能 | 用户可收藏常用配置项，在侧边栏快速访问 |
| 导入导出 | 支持JSON格式导入导出配置 |

### 3.3 配置分类

| 分类 | 图标 | 包含内容 |
|------|------|----------|
| 凭证管理 | 🔑 | LLM提供商API密钥、Base URL |
| AI模型配置 | 🤖 | 各场景模型选择、温度参数、max_tokens等 |
| RAG知识库 | 📚 | 检索策略、分块设置、向量存储、阈值 |
| 业务规则 | ⚙️ | 校验规则、评分规则、预处理规则 |
| 系统设置 | 📦 | 日志配置、路径配置、应用设置 |

## 四、向导模式设计

### 4.1 步骤流程

```
┌─────────────────────────────────────────────────────────────┐
│  步骤 1/3：  → 基础配置  │  高级配置  │  系统设置           │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  🔑 基础配置                                                  │
│  配置LLM提供商的API密钥和基础模型选择，这是系统运行的必要配置  │
│                                                              │
│  ┌──────────────────────────────────────────────────────┐   │
│  │ DashScope API Key                          * 必填     │   │
│  │ 阿里云百炼平台的API密钥，用于调用通义千问模型           │   │
│  │ [sk-____________________________________]            │   │
│  │ 💡 推荐：使用 qwen-max 模型获得最佳效果                │   │
│  └──────────────────────────────────────────────────────┘   │
│                                                              │
│  [跳过此步 (使用默认)]                    [下一步 →]         │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 步骤定义

| 步骤 | 名称 | 包含分类 | 跳过行为 |
|------|------|----------|----------|
| 1 | 基础配置 | 凭证管理 + 核心场景模型 | 使用.env.dev默认值 |
| 2 | 高级配置 | RAG知识库 + 业务规则 | 使用系统推荐配置 |
| 3 | 系统设置 | 系统设置 + 其他配置 | 使用出厂默认值 |

### 4.3 向导特性

- **可跳过**：每步可跳过，跳过则使用默认值
- **推荐默认值**：不跳过也提供推荐默认值，用户可直接确认
- **进度保存**：向导过程中修改自动保存到draftChanges
- **随时切换**：可随时切换回专家模式，不丢失进度

## 五、LLM健康度诊断设计

### 5.1 诊断流程

```
用户修改配置
    ↓
延迟30秒（防抖）
    ↓
收集当前配置JSON
    ↓
调用LLM (qwen-turbo)
    ↓
解析诊断结果
    ↓
更新HealthScoreCard
    ↓
缓存结果 (5分钟)
```

### 5.2 诊断Prompt设计

```
你是一个儿童发展评估系统的配置专家。请分析以下配置：

当前配置：
{config_json}

已知问题：
{current_issues}

使用场景：
{usage_context}

请输出JSON格式的诊断报告：
{
  "score": 0-100,
  "score_basis": "评分依据说明",
  "suggestions": [
    {
      "priority": "high|medium|low",
      "issue": "问题描述",
      "suggestion": "优化建议",
      "config_path": "配置项路径",
      "current_value": "当前值",
      "recommended_value": "推荐值"
    }
  ]
}
```

### 5.3 缓存与降级策略

| 策略 | 说明 |
|------|------|
| 触发时机 | 配置修改后30秒自动触发（防抖） |
| 缓存有效期 | 5分钟 |
| 手动刷新 | 点击"重新诊断"按钮 |
| 降级策略 | LLM调用失败时使用本地规则评分 |
| 成本控制 | 使用轻量模型（qwen-turbo） |

### 5.4 本地规则评分（降级备用）

| 配置类别 | 权重 | 评分规则 |
|----------|------|----------|
| LLM凭证 (API Key) | 30% | 至少配置1个提供商得满分，未配置得0分 |
| 核心场景模型 | 25% | 报告生成、评估场景使用推荐模型得满分 |
| RAG配置 | 20% | 检索策略、分块大小配置合理得满分 |
| 业务规则 | 15% | 校验规则、评分规则配置完整得满分 |
| 系统设置 | 10% | 日志、路径等基础配置正确得满分 |

## 六、模式切换设计

### 6.1 切换方式

- **用户偏好设置**：首次使用时选择偏好模式，之后默认进入该模式
- **切换入口**：
  - 专家模式：侧边栏底部"→ 向导模式"链接
  - 向导模式：步骤导航栏左侧"← 切换专家模式"链接
- **偏好存储**：localStorage + ConfigStore同步

### 6.2 数据共享

- 两种模式编辑**同一份配置数据**
- draftChanges在模式切换时**不丢失**
- 切换时不触发保存，仅切换UI展示方式
- 未保存修改在切换后继续保留
