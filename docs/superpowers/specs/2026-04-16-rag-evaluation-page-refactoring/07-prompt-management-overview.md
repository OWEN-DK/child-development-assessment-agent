# 07 - 提示词管理重构概览

> **本文档包含**: 提示词管理重构需求、用户痛点分析、重构策略、与现有系统联动关系

---

## 1. 用户需求声明

### 1.1 核心痛点

当前提示词管理存在以下问题:

| 痛点 | 严重程度 | 说明 |
|------|---------|------|
| **页面体验差** | CRITICAL | 现有页面仅为基础 CRUD，无版本对比可视化、无影响分析、无测试沙箱 |
| **改动风险高** | CRITICAL | 用户修改提示词后，无法知道会影响哪些代码逻辑，缺少变量校验和影响分析 |
| **配置不透明** | HIGH | 提示词与配置参数耦合，修改提示词中的参数引用时，不知道需要同步修改配置 |
| **缺少中文说明** | HIGH | 提示词 key 为英文（如 `rag_query_rewrite`），无中文名称和用途说明 |
| **降级文件维护困难** | MEDIUM | `prompts_fallback.py` 与数据库版本可能不同步，无自动化机制 |

### 1.2 用户心智模型

用户修改提示词时，本质要完成 **3 个核心任务**:

| 任务 | 用户心智模型 | 当前系统问题 |
|------|-------------|-------------|
| **1. 理解** | "这个提示词是干什么的？用了哪些变量？" | 无中文说明，无变量可视化 |
| **2. 修改** | "我改了提示词，会影响什么？" | 无影响分析，无变量校验 |
| **3. 验证** | "改完后效果怎么样？" | 无测试沙箱，无效果预览 |

### 1.3 核心原则

```
系统角色：辅助决策者（提供影响分析、变量校验、效果预览）
用户角色：最终决策者（审查影响、判断是否需要同步改代码、执行保存）

错误设计：检测到变量变化 → 自动更新代码引用
正确设计：检测到变量变化 → 展示影响范围 → 用户决定如何处理
```

## 2. 第一性原理分析

### 2.1 提示词的本质是什么？

提示词不是简单的文本字符串，而是 **代码与数据的契约**:

```
提示词 = 模板文本 + 变量声明 + 代码引用 + 配置参数引用
```

因此，提示词管理不能只是文本编辑，必须包含:
1. **变量管理** - 声明、校验、变更检测
2. **影响分析** - 代码引用位置、配置参数依赖
3. **版本控制** - 历史对比、回滚能力
4. **效果验证** - 测试沙箱、输出预览

### 2.2 当前系统的根本问题

**不是"功能不够"，而是"契约断裂"**：

```
期望工作流：
查看提示词 → 理解用途 → 修改内容 → 系统提示影响 → 用户确认 → 保存 → 测试验证

当前工作流：
查看提示词 → ❌ 不知道用途 → 修改内容 → ❌ 不知道影响 → 保存 → ❌ 无法验证
```

## 3. 重构策略

### 3.1 核心原则

| 原则 | 说明 | 落地 |
|------|------|------|
| **契约优先** | 提示词是代码与数据的契约，修改必须告知影响 | 变量变更检测 + 代码引用分析 |
| **用户决策** | 系统只提供信息，不替用户做决策 | 影响分析仅展示，不自动应用 |
| **零历史包袱** | 项目未上线，不存在旧数据迁移 | 全新设计，不写兼容代码 |
| **中文优先** | 所有提示词必须有中文名称和用途说明 | 数据模型新增 `name_zh`、`purpose` 字段 |

### 3.2 信息架构

```
提示词管理
├── 📋 提示词列表
│   ├── 中文名称 + 用途说明
│   ├── 当前版本号 + 最后修改时间
│   └── 使用状态（是否被代码引用）
│
├── ✏️ 提示词编辑
│   ├── 内容编辑区（支持语法高亮）
│   ├── 变量可视化面板（自动提取 {variable}）
│   ├── 影响分析面板（代码引用位置 + 配置参数依赖）
│   └── 保存按钮（触发变量校验）
│
├── 🔍 版本管理
│   ├── 版本列表（版本号 + 修改人 + 时间 + 描述）
│   ├── 版本对比（diff 可视化）
│   └── 版本回滚
│
├── 🧪 测试沙箱
│   ├── 输入变量填写表单
│   ├── 预览 LLM 输出
│   └── 对比新旧版本输出差异
│
└── ⚠️ 影响分析
    ├── 代码引用位置（文件路径 + 行号）
    ├── 配置参数依赖（参数名 + 当前值）
    └── 变量变更警告（新增/删除/修改的变量）
```

## 4. 与现有系统联动关系

### 4.1 与 RAG 评估页面的联动

| 联动点 | 说明 | 触发条件 |
|--------|------|---------|
| **调优建议应用** | RAG 评估页的调优建议可包含提示词修改建议 | 用户点击"应用建议"时跳转到提示词编辑页 |
| **版本对比** | 评估报告展示提示词版本变更对指标的影响 | 报告页展示"提示词变更 → 指标变化"关联图 |
| **回溯测试** | 修改提示词后可快速运行回溯测试验证效果 | 保存提示词新版本后，提示用户"是否运行回溯测试？" |

### 4.2 与配置管理的联动

| 联动点 | 说明 | 触发条件 |
|--------|------|---------|
| **参数引用检测** | 提示词中引用的配置参数（如 `{threshold}`）需在配置管理页展示 | 提示词编辑时自动检测并展示依赖的配置参数 |
| **联动修改** | 修改配置参数时，提示哪些提示词引用了该参数 | 配置编辑页展示"引用此参数的提示词列表" |

## 6. 术语表

| 术语 | 定义 |
|------|------|
| **Prompt Key** | 提示词唯一标识符，如 `rag_query_rewrite` |
| **变量（Variable）** | 提示词模板中的占位符，如 `{query}`、`{age}` |
| **影响分析（Impact Analysis）** | 分析提示词修改对代码、配置、其他提示词的影响 |
| **测试沙箱（Test Sandbox）** | 提供测试输入，预览提示词修改后的 LLM 输出效果 |
| **代码引用（Code Reference）** | 代码中使用 `prompt_manager.get_prompt(key)` 的位置 |
| **配置参数依赖（Config Dependency）** | 提示词中引用的配置参数，如 `{rag_similarity_threshold}` |
