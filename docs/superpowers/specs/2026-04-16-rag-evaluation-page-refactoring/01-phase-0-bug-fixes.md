# 01 - Phase 0: 核心工作流修复

> **需求来源**: 00-overview.md 中 1.3 和 1.4 节已定位的 12 个根因，必须在 Phase 1 新功能实施前修复，否则核心工作流断裂。

---

## 2.0 Phase 0: 核心工作流修复 (实施前提)

### 2.0.1 书籍导入修复需求

| 根因 | 修复需求 | 验收标准 |
|------|---------|---------|
| EventSource 相对路径 | 前端 SSE 连接必须使用绝对路径 (含协议、域名、端口) | 开发环境 (5173→8000) 和生产环境 SSE 连接均成功 |
| PDF/EPUB 二进制读取 | 系统必须使用专用解析器处理不同格式 (PDF→pypdf2, EPUB→ebooklib, TXT→文本读取) | 上传 PDF/EPUB/TXT 三类文件均能正确提取文本内容 |
| DASHSCOPE_API_KEY 未配置 | 系统启动时必须校验 LLM 环境变量，缺失时在前端展示明确错误提示 | 环境变量缺失时，前端显示"LLM 服务未配置，请联系管理员" |
| Redis 依赖问题 | 系统必须检测 Redis 可用性，不可用时降级到内存队列模式 | Redis 未启动时，SSE 推送仍可通过内存队列正常工作 |
| asyncio.create_task 无引用 | 后台任务必须保持强引用，防止被 GC 回收 | 长时间任务 (10min+) 不会静默终止 |

### 2.0.2 批量测试修复需求

| 根因 | 修复需求 | 验收标准 |
|------|---------|---------|
| 前端无 SSE 监听 | 批量测试必须通过 SSE 推送进度，前端不得等待 HTTP 响应 | 前端能实时显示进度百分比和当前处理用例 |
| runSingleTest 调用 runAllTests | 单个用例测试必须严格只运行该用例，不得执行其他用例 | 传入 caseId 后，仅执行对应用例 |
| RetrievalService 重复初始化 | 批量测试必须复用同一个 RetrievalService 实例 | 128 用例测试不出现连接池耗尽 |
| 分布式锁对唯一 run_id 无意义 | 批量测试不得依赖分布式锁，应使用本地并发控制 | Redis 不可用时批量测试仍能执行 |
| complete_test_run 读到不完整数据 | 测试完成后必须等待所有用例结果聚合完毕再计算指标 | 报告指标与用例执行结果一致 |
| SSE 心跳队列内存泄漏 | 前端断开连接时，后端必须清理对应心跳队列 | 前端刷新页面后，后端队列内存释放 |
| 前端 API 超时 30 秒 | 前端发起批量测试后不得设置 HTTP 超时，改为依赖 SSE 进度事件 | 批量测试超过 30 秒不触发前端超时错误 |
