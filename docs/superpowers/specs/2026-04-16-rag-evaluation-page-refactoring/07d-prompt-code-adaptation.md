# 07d - 提示词代码适配策略

> **本文档包含**: 用户修改提示词后如何保证与代码适配的策略、变量改动处理流程

---

## 1. 核心问题

**用户改动提示词时，什么情况下需要同步修改代码？**

### 1.1 不需要改代码的情况

| 改动类型 | 示例 | 是否需要改代码 |
|---------|------|--------------|
| **文案优化** | "你是专家" → "你是资深专家" | ❌ 不需要 |
| **格式调整** | 调整段落顺序、增加换行 | ❌ 不需要 |
| **内容扩充** | 增加更多说明文字 | ❌ 不需要 |
| **变量值变化** | 变量不变，只是变量上下文描述变化 | ❌ 不需要 |

### 1.2 需要改代码的情况

| 改动类型 | 示例 | 需要改代码的位置 |
|---------|------|----------------|
| **新增必填变量** | 内容中新增 `{goals}`，且 schema 中标记为 required | 调用 `get_prompt()` 时传入 `variables={"goals": "..."}` |
| **删除变量** | 内容中删除 `{age}` | 调用处可删除该变量传入 |
| **变量重命名** | `{child_age}` → `{age}` | 调用处修改变量名 |
| **配置参数引用变化** | 新增引用 `{rag_new_threshold}` | 确保配置管理中该参数存在 |

## 2. 适配策略

### 2.1 核心原则

```
系统角色：辅助决策者（检测变量变化、展示影响范围、提供修改建议）
用户角色：最终决策者（判断是否需要同步改代码、执行修改）

错误设计：检测到变量变化 → 自动修改代码调用
正确设计：检测到变量变化 → 展示影响范围 + 修改建议 → 用户决定是否改代码
```

### 2.2 检测流程

1. 用户保存提示词新版本
2. 系统自动检测变量变化
3. 如果变量无变化：提示"变量无变化，无需修改代码"
4. 如果变量有变化：
   - 生成影响报告
   - 展示：哪些变量变化了（新增/删除/重命名）、哪些代码文件引用了此提示词、每个引用位置需要如何修改
   - 用户审查影响报告
   - 用户决定是否修改代码
   - 用户手动修改代码（系统不自动修改）

---

## 3. 影响报告格式

### 3.1 变量无变化

返回：prompt_key、版本号、variable_change（added/removed/renamed 均为空）、code_adaptation_required=false、提示信息。

### 3.2 变量有变化

返回：prompt_key、版本号、variable_change（added/removed/renamed）、code_adaptation_required=true、affected_code 列表（每个包含：文件路径、行号、函数名、当前代码、建议代码、变化类型、变量名、变量说明）、提示信息。

---

## 4. 代码适配建议生成器

### 4.1 实现逻辑

1. 计算变量变化（added/removed/renamed）
2. 如果无变化，直接返回无需适配
3. 如果有变化，遍历每个代码引用位置：
   - 读取文件内容
   - 定位调用代码
   - 生成建议代码（根据变化类型在 variables 字典中新增/删除/修改变量）
4. 返回完整的影响报告

### 4.2 建议代码生成规则

| 变化类型 | 建议代码生成规则 |
|---------|----------------|
| **新增变量** | 在 `variables={...}` 中新增 `"new_var": new_var` |
| **删除变量** | 从 `variables={...}` 中移除 `"old_var"` |
| **变量重命名** | 将 `"old_name"` 改为 `"new_name"` |

---

## 5. 前端展示

### 5.1 保存后的影响提示

保存新版本后，如果检测到变量变化，弹出影响提示框：
- 展示变量变化列表（新增/删除/重命名）
- 展示受影响的代码位置（文件路径、行号、函数名）
- 每个位置展示当前代码和建议修改代码
- 提供操作：复制建议代码、同步到降级文件、标记已处理、导出完整报告

### 5.2 交互流程

1. 用户保存新版本
2. 系统检测变量变化
3. 如果变量无变化：提示"变量无变化，无需修改代码"，流程结束
4. 如果变量有变化：
   - 弹出影响提示框
   - 展示受影响的代码位置和建议修改
   - 用户可：复制建议代码手动修改、同步到降级文件、标记已处理、导出完整报告
   - 用户手动修改代码后，点击"关闭提示"

## 6. 降级文件自动同步

### 6.1 同步策略

**设计决策**: `prompts_fallback.py` 是唯一允许自动同步的文件，因为:
- 它是降级备用文件，必须与数据库版本一致
- 同步不会影响业务逻辑，只是更新备用内容
- 用户无法"拒绝"同步，因为这是系统一致性保障

### 6.2 同步实现

维护 prompt_key 到降级文件常量的映射表。同步时：
1. 读取降级文件
2. 替换对应常量内容
3. 写回文件

---

## 7. 配置参数联动

### 7.1 配置参数变化影响

当用户修改配置参数时，系统需要提示哪些提示词引用了该参数。

API: `GET /api/v1/config/:param/impact`

返回：参数信息、引用此参数的提示词列表（含引用上下文）。

### 7.2 配置编辑页联动展示

在配置编辑页展示"引用此参数的提示词列表"，每个提示词展示引用上下文片段，提供"查看提示词"跳转链接。

---

## 8. 验收标准

| 验收项 | 标准 |
|--------|------|
| **变量检测** | 准确检测新增、删除、重命名变量 |
| **影响报告** | 格式正确，包含所有必要字段和建议代码 |
| **前端展示** | 影响提示框正常弹出，建议代码可复制 |
| **降级文件同步** | 同步后 `prompts_fallback.py` 内容与数据库一致 |
| **配置联动** | 配置编辑页正确展示引用此参数的提示词列表 |
| **性能** | 影响分析生成时间 < 1 秒 |
