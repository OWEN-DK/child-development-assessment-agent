# 07c - 提示词影响分析引擎

> **本文档包含**: 影响分析引擎设计、代码引用扫描、变量校验、配置参数依赖检测

---

## 1. 核心任务

影响分析引擎要解决的核心问题:

**"用户修改提示词后，如何知道会影响什么？"**

---

## 2. 影响分析维度

### 2.1 变量变更检测

| 检测项 | 说明 | 触发条件 |
|--------|------|---------|
| **新增变量** | 新版本内容中出现了旧版本没有的 `{variable}` | 保存新版本时 |
| **删除变量** | 旧版本中存在的 `{variable}` 在新版本中消失 | 保存新版本时 |
| **修改变量** | 变量名不变，但变量上下文描述发生变化 | 保存新版本时 |

### 2.2 代码引用分析

| 检测项 | 说明 | 扫描方式 |
|--------|------|---------|
| **直接引用** | 代码中使用 `prompt_manager.get_prompt("key")` | AST 扫描 |
| **间接引用** | 代码中通过变量拼接 key（如 `get_prompt(f"rag_{type}")`） | 正则扫描 |
| **降级引用** | `prompts_fallback.py` 中对应的常量 | 文件扫描 |

### 2.3 配置参数依赖检测

| 检测项 | 说明 | 检测方式 |
|--------|------|---------|
| **参数引用** | 提示词内容中包含配置参数（如 `{rag_similarity_threshold}`） | 正则匹配 |
| **模型引用** | 提示词使用的 LLM 模型（通过场景配置关联） | 元数据关联 |

---

## 3. 代码引用扫描器

### 3.1 扫描策略

**设计决策**: 采用 AST + 正则混合扫描，因为:
- AST 扫描准确，但无法处理动态拼接的 key
- 正则扫描覆盖动态场景，但有误报风险
- 混合扫描平衡准确率和覆盖率

### 3.2 扫描规则

- **AST 扫描**: 匹配 `prompt_manager.get_prompt()` 调用，提取 prompt_key 参数值
- **正则扫描**: 匹配 `prompt_manager.get_prompt("key")`、`get_prompt("key")`、`prompt_key = "key"` 等模式

### 3.3 扫描输出格式

扫描结果按 prompt_key 分组，每个引用包含：文件路径、行号、列号、函数名、调用代码上下文、扫描方式（ast/regex）。

---

## 4. 变量校验器

### 4.1 校验流程

1. 用户保存新版本
2. 提取新版本内容中的所有 `{variable}`
3. 与 variables_schema 对比
4. 生成变更报告：
   - variables_added: 新增变量列表
   - variables_removed: 删除变量列表
   - variables_missing: 声明但未使用变量列表
   - variables_undeclared: 使用但未声明变量列表
5. 如果 variables_missing 或 variables_undeclared 非空：返回警告，允许强制保存
6. 如果 variables_added 或 variables_removed 非空：返回提示，建议更新 variables_schema

### 4.2 校验规则

- 从内容中提取所有匹配 `\{([a-zA-Z_][a-zA-Z0-9_]*)\}` 的变量名
- 与 schema 中的变量集合计算差集
- 检查必填变量是否缺失

---

## 5. 配置参数依赖检测器

### 5.1 检测策略

配置参数依赖通过正则匹配提示词内容中的 `{param_name}` 格式，与系统配置元数据对比。

### 5.2 检测输出格式

每个依赖包含：参数名、分类、说明、当前值、是否支持热重载。

---

## 6. 影响分析 API

### 6.1 获取影响分析结果

`GET /api/v1/prompts/:key/impact`

返回：prompt_key、当前版本、代码引用列表、配置依赖列表、相关提示词列表（同属一个流水线的提示词）。

### 6.2 保存新版本时的影响分析

`POST /api/v1/prompts/:key/versions`

返回：新版本号、变量校验报告、影响分析（受影响的代码引用数量、配置依赖是否变化、建议）。

---

## 7. 手动触发扫描

### 7.1 扫描触发时机

| 触发方式 | 说明 |
|---------|------|
| **自动扫描** | 系统启动时自动扫描所有提示词引用 |
| **手动扫描** | 用户在提示词管理页点击"刷新引用"按钮 |
| **CI 扫描** | Git push 时触发 CI 钩子，更新 `code_references` |

### 7.2 扫描 API

`POST /api/v1/prompts/scan`

返回：状态、扫描文件数、引用数量、更新的提示词列表、耗时。

---

## 8. 验收标准

| 验收项 | 标准 |
|--------|------|
| **代码引用扫描** | 准确扫描所有 `prompt_manager.get_prompt()` 调用 |
| **变量校验** | 正确检测新增、删除、缺失、未声明变量 |
| **配置依赖检测** | 正确识别提示词中引用的配置参数 |
| **影响分析报告** | 格式正确，包含所有必要字段 |
| **手动扫描** | 扫描触发后 2 秒内完成 |
| **缓存机制** | 扫描结果缓存 1 小时，避免重复扫描 |
