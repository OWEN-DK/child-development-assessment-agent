## ⚠️ 用户需求声明 (实施前必读)

> **以下需求来自用户直接反馈，实施方案必须严格遵守，不可偏离：**

### 🎯 用户画像
- **用户是懂技术的**（配置管理、提示词管理、回溯测试的使用者都有技术背景）
- **不是小白用户**，不需要"一键优化"式的傻瓜操作

### 🚫 禁止事项

1. **禁止替用户做决策** — 推荐只是参考，不能自动应用配置
2. **禁止隐藏决策依据** — 每个推荐必须解释"为什么改"
3. **禁止跳过对比环节** — 用户必须能看到改动前后的差异
4. **禁止省略影响分析** — 用户需要知道"改了会有什么后果"
5. **禁止兼容历史版本** — 项目未上线，不存在旧数据/旧接口/旧页面迁移需求，任何方案不得包含兼容性代码、迁移脚本、双版本并行逻辑

### ✅ 必须事项
1. **必须展示前后对比** — 配置值 diff、提示词内容 diff
2. **必须说明改动原因** — 触发条件、指标短板、Bad Case 分析
3. **必须预览改动影响** — 预期指标变化、风险警告、历史参考
4. **必须让用户手动确认** — 采纳 → 审查 → 保存为新版本，三步分离
5. **必须支持回溯** — 每次修改留版本记录，可回滚

### 🔐 权限策略 (明确决策)
```
当前阶段：不需要 RBAC（基于角色的访问控制）
原因：项目处于内部开发/测试阶段，用户均为技术人员，无多租户/权限隔离需求
落地：
  - 所有资源（测试集/报告/配置/提示词）对登录用户可见可操作
  - 数据模型中的 created_by/ignored_by/annotated_by 字段仅用于审计追踪，不用于权限控制
  - SSE 连接不做用户级隔离
  - 后续如需多用户权限隔离，可在此阶段之后独立迭代
```

### 💡 核心原则
```
系统角色：辅助决策者（提供信息、分析、建议）
用户角色：最终决策者（审查、判断、执行）

错误设计：检测到问题 → 自动应用推荐配置
正确设计：检测到问题 → 展示原因+对比+影响 → 用户决定是否采纳
```

## 1. 第一性原理分析

### 1.1 用户的核心任务是什么？

用户打开这个页面，本质上要完成 **3 个核心任务**：

| 任务 | 用户心智模型 | 当前页面问题 |
|------|-------------|-------------|
| **1. 诊断** | "我的 RAG 检索质量怎么样？哪里有问题？" | 指标全 0，无诊断能力 |
| **2. 调优** | "我调了参数，效果有没有变好？" | 无对比分析，无法验证 |
| **3. 数据** | "我要导入书籍生成测试用例" | 书籍导入失败，核心工作流中断 |

### 1.2 当前页面的本质问题

**不是"功能不够"，而是"工作流断裂"**：

```
期望工作流：
导入书籍 → 生成测试用例 → 运行诊断 → 查看问题 → 调参 → 验证效果 → 循环

当前工作流：
导入书籍 → ❌ 失败 → 无法生成用例 → 无法运行诊断 → 页面空白
```

### 1.3 书籍导入失败的根因（已定位）

| 失败点 | 严重程度 | 根因 |
|--------|---------|------|
| **EventSource 相对路径** | CRITICAL | 前端 dev server (5173) 和后端 (8000) 端口不同，SSE 请求 404 |
| **PDF/EPUB 二进制读取** | CRITICAL | 用文本模式读取二进制文件，产生乱码 |
| **DASHSCOPE_API_KEY 未配置** | CRITICAL | 环境变量缺失，LLM 调用失败 |
| **Redis 依赖问题** | HIGH | SSE 依赖 Redis Pub/Sub，Redis 未启动时消息丢失 |
| **asyncio.create_task 无引用** | HIGH | Task 可能被 GC，导致任务静默终止 |

### 1.4 批量测试失败的根因（已定位）

| 问题 | 严重程度 | 根因 |
|------|---------|------|
| **前端无 SSE 监听** | CRITICAL | 前端发 POST 后等待 HTTP 响应，但批量测试远超 30 秒超时 |
| **runSingleTest 调用 runAllTests** | CRITICAL | 代码 Bug：`_caseId` 参数被忽略，实际运行了所有测试 |
| **asyncio.create_task 无引用** | HIGH | 后台任务可能被 GC 回收 |
| **RetrievalService 重复初始化** | HIGH | 每个用例创建新实例，并发时耗尽连接池 |
| **分布式锁对唯一 run_id 无意义** | MEDIUM | 增加复杂度，Redis 故障时导致失败 |
| **complete_test_run 读到不完整数据** | MEDIUM | 聚合指标可能不准确 |
| **SSE 心跳队列内存泄漏** | LOW | 前端无消费，队列无限增长 |
| **前端 API 超时 30 秒** | HIGH | 批量测试通常远超 30 秒 |

## 2. 重构策略

### 2.1 核心原则

| 原则 | 说明 | 落地 |
|------|------|------|
| **零历史包袱** | 项目未上线，不存在旧数据/旧接口/旧页面 | 全新设计，不写兼容代码、不写迁移脚本、不做双版本并行 |
| **以测试集为核心** | 所有操作围绕测试集展开 | 测试集 → 用例 → 运行 → 报告 → 调优 → 复测 |
| **分层递进诊断** | 从快速规则到深度 LLM 诊断 | 规则引擎 → 历史对比 → LLM 诊断 |
| **报告驱动调优** | 报告页面直接集成配置/提示词编辑 | 推荐模式面板，采纳→审查→保存 |
| **渐进式披露** | 从概览到详情，不一次性展示所有信息 | 推荐区 + 其他配置区分离 |

### 2.2 系统定位

这是一个**以测试集为核心的 RAG 评估平台**，核心工作流：

```
创建/选择测试集 → 运行测试集 → 生成评估报告 → 校验诊断 → 输出调优建议 → 应用建议 → 复测验证
```

### 2.3 信息架构

```
RAG 评估平台
├── 📊 测试集管理 (Test Sets)          ← 核心：测试数据组织
│   ├── 测试集列表/创建/编辑
│   ├── 测试用例管理 (含 Golden Dataset)
│   ├── 草稿审核
│   └── 数据导入 (JSON + 书籍)
│
├── 🏃 运行历史 (Runs)                ← 核心：测试执行记录
│   ├── 运行列表
│   └── 运行详情 + SSE 进度
│
├── 📋 评估报告 (Reports)             ← 核心：诊断 + 调优
│   ├── 指标总览 (Precision/Recall/F1/MRR/NDCG)
│   ├── 6 层校验结果 (问题定位)
│   │   ├── Layer 1: 规则引擎 (指标阈值 → 参数建议)
│   │   ├── Layer 2: 历史对比 (配置变更 → 指标变化)
│   │   ├── Layer 3: LLM 诊断 (Bad Case 语义分析)
│   │   ├── Layer 4: 数据质量 (Golden覆盖度 + 分块质量 + 文档时效)
│   │   ├── Layer 5: 检索链路 (Embedding质量 + 意图识别 + 错误模式分组)
│   │   └── Layer 6: 验证保障 (回归检测 + 交叉验证 + 成本效果 + A/B影子)
│   ├── 调优建议 (去重合并后)
│   ├── 配置/提示词推荐模式面板 (右侧集成)
│   └── 趋势追踪 (历史运行对比)
│
└── 🔧 配置/提示词编辑 (集成在报告页)  ← 核心：报告驱动调优
    ├── 推荐模式 (默认): 仅展示被触发的参数 + 建议值
    ├── 向导模式: 按功能域分组，关键参数优先
    └── 专家模式: 全量配置参数树
```

## 3. 术语表

| 术语 | 定义 |
|------|------|
| **RAG** | Retrieval-Augmented Generation，检索增强生成 |
| **Golden Dataset** | 标准测试集，包含查询和期望答案 |
| **Precision@K** | 前 K 个检索结果中相关文档的比例 |
| **Recall@K** | 检索到的相关文档占所有相关文档的比例 |
| **F1 Score** | Precision 和 Recall 的调和平均数 |
| **MRR** | Mean Reciprocal Rank，平均倒数排名 |
| **NDCG** | Normalized Discounted Cumulative Gain，归一化折损累计增益 |
| **Bad Case** | 测试失败的用例，指标低于阈值 |
| **SSE** | Server-Sent Events，服务器推送事件 |
| **ConfigVersion** | 配置版本，记录某时刻的完整配置快照 (JSON 存储) |
| **PromptVersion** | 提示词版本，记录某时刻的提示词内容 |
| **ConfigChangeSet** | 配置变更集，原子保存配置+提示词的整体版本 |
| **TestReport** | 评估报告，每次运行生成一份，包含 6 层校验结果 |
| **TuningSuggestionRecord** | 调优建议记录，包含参数/提示词的当前值、建议值、原因 |
| **IntentAnnotation** | 意图人工标注，Layer 5b 校验的数据来源 |
| **TestSetCase** | 测试集-用例关联表，支持用例被多个测试集复用 |
