# 06 - 参考指标体系

> **以下指标体系来自用户直接指定，系统必须支持这些指标的计算、展示和趋势追踪。这些指标是诊断和调优的核心依据，不可省略。**

---

## 8.1 检索阶段核心指标

| 指标 | 用途 | 达标阈值 | 说明 |
|------|------|---------|------|
| **精确率 (Precision)** | 衡量检索返回的文档片段中，与用户问题真正相关的内容占比，用于识别检索结果是否混入大量噪声文档 | P@5 ≥ 0.70 | 识别噪声文档过多问题 |
| **召回率 (Recall)** | 衡量知识库中所有与问题相关的文档片段里，被成功检索返回的内容占比，用于判断检索是否遗漏了关键信息 | R@5 ≥ 0.85 | 判断关键信息遗漏 |
| **F1 分数** | 精确率和召回率的调和平均值，用于平衡二者之间的天然张力，综合评估检索的基础效果，帮助找到检索 Top-K 的最优取值 | F1 ≥ 0.75 | 综合评估检索基础效果 |
| **平均倒数排名 (MRR)** | 衡量检索结果中第一个相关文档的排序位置，得分越高代表系统越能把最相关的结果排在前列，保障核心信息优先被大模型获取 | MRR ≥ 0.70 | 保障核心信息优先获取 |
| **归一化折损累积增益 (NDCG)** | 全面评估整个检索排序列表的质量，不仅考虑全量结果的相关性，还支持多级相关性标注，同时对排序靠后的文档做贡献度折损，更贴合 RAG 场景的排序需求 | NDCG ≥ 0.70 | 评估整个排序列表质量 |
| **上下文相关性 (Context Relevance)** | 由 RAGAS 框架提出，评估检索返回的整体上下文中，能真正用于回答用户问题的有效内容占比，可精准识别"检索内容多但有效信息少"的低效检索问题 | ≥ 0.75 | 识别低效检索 |

---

## 8.2 生成阶段核心指标

| 指标 | 用途 | 达标阈值 | 说明 |
|------|------|---------|------|
| **忠实度 (Faithfulness)** | RAG 生成评估的核心指标，衡量大模型生成的回答是否忠实于检索到的文档内容，是否编造了检索结果中不存在的信息，是保障 RAG 系统基于可靠外部知识回答的核心标尺 | ≥ 0.80 | 保障回答基于可靠知识 |
| **回答相关性 (Answer Relevance)** | 衡量生成的回答是否切题、是否真正回应了用户的问题，规避内容忠实但答非所问的低质量回答问题 | ≥ 0.80 | 规避答非所问 |
| **回答完整性 (Answer Completeness)** | 评估生成的回答是否覆盖了用户问题的所有核心要点，通常结合标注的参考答案对比关键信息点的覆盖情况，衡量回答的完整度 | ≥ 0.75 | 评估要点覆盖 |
| **回答正确性 (Answer Correctness)** | 衡量生成的回答的事实准确性，结合参考答案对比关键信息点的正确性 | ≥ 0.75 | 评估事实准确性 |

---

## 8.3 传统 NLP 辅助评估指标

| 指标 | 用途 | 定位 | 说明 |
|------|------|------|------|
| **BLEU** | 原本用于机器翻译评估，衡量生成文本与参考文本之间的 n-gram 重叠度，计算简单、无额外调用成本 | 辅助粗筛 | 仅可作为 RAG 评估的辅助参考，不能作为核心评估手段 |
| **ROUGE** | 原本用于文本摘要评估，侧重衡量参考文本中的关键 n-gram 是否被生成文本覆盖，计算成本极低 | 辅助粗筛 | 仅可作为 RAG 生成文本语义质量的辅助参考，无法衡量语义层面的匹配度 |
| **BERTScore** | 基于预训练语言模型的 Embedding 计算生成文本与参考文本的语义相似度，解决了传统指标"同义不同词"的缺陷 | 辅助参考 | 可作为 RAG 生成文本语义质量的辅助评估指标 |

---

## 8.4 端到端与整体闭环评估指标

| 指标 | 用途 | 说明 |
|------|------|------|
| **端到端回答正确性 (Answer Correctness)** | 端到端自动化评估核心指标，用于 RAG 系统版本间的效果对比与发布前的回归检测，整体衡量最终回答的综合质量 | 版本对比与回归检测 |
| **RAGAS 综合分数** | 基于 RAGAS 框架的综合自动化评估指标，用于版本间的整体效果对比，实现 RAG 系统迭代的快速效果验证 | 整体效果验证 |
| **人工评估 + 用户反馈** | RAG 评估体系的顶层校准环节，用于校准自动化评估指标的准确性，把握真实的用户体验，通常采用定期抽检的方式执行 | 顶层校准 |

---

## 指标在系统中的落地

| 指标类别 | 系统落地位置 | 存储方式 | 说明 |
|---------|-------------|---------|------|
| **检索阶段指标** (Precision/Recall/F1/MRR/NDCG/Context Relevance) | Layer 1 规则引擎阈值触发 | TestReport.precision/recall/f1/mrr/ndcg + validation_results JSON (Context Relevance) | Context Relevance 存储在 validation_results 中，作为检索质量辅助指标 |
| **生成阶段指标** (Faithfulness/Answer Relevance/Completeness/Correctness) | Layer 3 LLM 诊断扩展 | validation_results JSON (Layer 3 输出包含生成质量评分) | 通过 LLM 对 Bad Case 的检索结果 + 期望答案进行评估 |
| **传统 NLP 指标** (BLEU/ROUGE/BERTScore) | 报告页"辅助指标"折叠区 | validation_results JSON (可选) | 标注"仅供参考"，不作为核心决策依据 |
| **端到端指标** (Answer Correctness/RAGAS Score) | 趋势追踪 | validation_results JSON (Layer 6 输出) | 在趋势图中展示，用于版本间对比 |
| **人工评估** | 报告页"标注反馈"入口 | IntentAnnotation 表 + 前端反馈标记 | 用户可标记报告中的指标是否与实际体验一致，用于校准自动化指标 |
