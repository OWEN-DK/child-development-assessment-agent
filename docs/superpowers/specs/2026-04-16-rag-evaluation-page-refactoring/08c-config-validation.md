# 08c - 配置校验引擎

> **本文档包含**: 配置校验规则、取值范围校验、推荐范围警告、冲突检测

---

## 1. 校验层级

配置校验分为 4 层：

| 层级 | 校验类型 | 是否阻止保存 |
|------|---------|-------------|
| Layer 1 | 类型校验（float/int/bool/str/Dict/List） | 是 |
| Layer 2 | 范围校验（最小值、最大值、枚举值、格式） | 是 |
| Layer 3 | 推荐范围警告（推荐最小值、推荐最大值、业务规则警告） | 否（仅警告） |
| Layer 4 | 冲突检测（互斥配置、依赖缺失、逻辑不一致） | 否（仅警告） |

---

## 2. Layer 1: 类型校验

### 2.1 校验规则

| 类型 | 校验规则 | 错误提示 |
|------|---------|---------|
| `float` | 必须为数字，可含小数 | "请输入有效的数字" |
| `int` | 必须为整数 | "请输入有效的整数" |
| `bool` | 必须为 true/false | "请选择开启或关闭" |
| `str` | 非空字符串 | "请输入配置值" |
| `Dict` | 合法 JSON 对象 | "请输入有效的 JSON 对象" |
| `List` | 合法 JSON 数组 | "请输入有效的列表" |

---

## 3. Layer 2: 范围校验

### 3.1 数值范围校验

- 枚举值校验：配置值必须在允许的枚举值列表中
- 最小值校验：配置值不能小于 min_value
- 最大值校验：配置值不能大于 max_value

### 3.2 格式校验

- URL 格式校验：验证是否符合标准 URL 格式
- 其他格式校验根据具体配置类型扩展

---

## 4. Layer 3: 推荐范围警告

### 4.1 警告规则

| 配置 | 推荐范围 | 超出警告 |
|------|---------|---------|
| BM25 权重 | [0.3, 0.7] | "过高可能导致 BM25 结果主导检索" / "过低可能导致语义匹配主导" |
| 向量权重 | [0.3, 0.7] | 同上 |
| 融合阈值 | [0.2, 0.3] | "过高可能导致无结果返回" / "过低可能引入噪声" |
| 分块大小 | [500, 1500] | "过大可能导致上下文不精确" / "过小可能丢失语义连贯性" |
| 缓存 TTL | [1800, 7200] | "过长可能导致数据不及时" / "过短可能增加计算开销" |

### 4.2 警告生成策略

为关键配置项预定义警告消息模板，根据配置 key 和超出方向（过高/过低）生成对应的警告信息。

---

## 5. Layer 4: 冲突检测

### 5.1 完整冲突规则列表

| 冲突规则 | 触发条件 | 级别 | 处理 |
|---------|---------|------|------|
| 权重和不等于 1 | `bm25_weight + vector_weight ≠ 1.0` (允许 ±0.01 浮点误差) | 🔴 阻止 | 阻止保存，提示"BM25 权重 + 向量权重必须等于 1" |
| final_k > initial_k | `reranker_final_k > reranker_initial_k` | 🔴 阻止 | 阻止保存，提示"重排序最终结果数不能大于初始结果数" |
| overlap ≥ chunk_size | `chunk_overlap >= chunk_size` | 🔴 阻止 | 阻止保存，提示"分块重叠不能大于等于分块大小" |
| TopK 不匹配 | `reranker_initial_k < bm25_top_k` 且 `reranker_initial_k < vector_top_k` | ⚠️ 警告 | 允许保存，提示"重排序初始结果数小于检索 TopK，重排序无意义" |
| 融合阈值极端 | `fusion_threshold < 0.15` 或 `fusion_threshold > 0.45` | ⚠️ 警告 | 允许保存，提示"融合阈值过于极端，可能导致单一检索源主导" |
| 查询重写未开启但同义词开启 | `query_rewrite_enabled = false` 且 `synonym_expansion_enabled = true` | ⚠️ 警告 | 允许保存，提示"同义词扩展依赖查询重写，建议同时开启" |
| 重排序未开启但 final_k 有值 | `reranker_enabled = false` 且 `reranker_final_k > 5` | ⚠️ 警告 | 允许保存，提示"重排序未开启，final_k 设置无意义" |
| 年龄过滤过严 + TopK 过小 | `age_filter_strictness > 0.8` 且 `bm25_top_k < 10` 且 `vector_top_k < 10` | ⚠️ 警告 | 允许保存，提示"年龄过滤过严且 TopK 过小，可能导致结果不足" |
| 缓存关闭但缓存大小有值 | `cache_enabled = false` 且 `cache_max_size > 0` | ⚠️ 警告 | 允许保存，提示"缓存已关闭，缓存大小设置无意义" |
| 查询重写和路由同时开启 | `query_rewrite_enabled = true` 且 `query_routing_enabled = true` | ⚠️ 警告 | 允许保存，提示"查询重写和查询路由同时开启可能导致重复处理" |

### 5.2 冲突检测实现

- 冲突规则硬编码在后端 `backend/src/core/config/conflict_detector.py` 中，使用规则引擎模式
- 每条规则定义为一个函数，返回 `{conflict: bool, level: "error" | "warning", message: str}`
- 新增冲突规则时，只需在规则注册表中添加新函数，无需修改校验流程
- 前端接收到冲突检测结果后，`error` 级别阻止保存并显示红色错误提示，`warning` 级别显示黄色警告提示但允许用户确认继续保存

### 5.3 互斥配置冲突

检测规则示例：
- 缓存关闭时，缓存大小配置无意义
- 查询重写和查询路由 LLM 同时开启可能导致重复处理

### 5.4 依赖配置缺失

检测规则示例：
- 重排序初始数量依赖重排序功能开启

### 5.5 逻辑不一致警告

检测规则示例：
- BM25 权重 + 向量权重应约等于 1.0（偏差超过 0.1 时警告）
- 重排序 initial_k 应大于 final_k
- 宽松模式年龄容忍度应大于等于严格模式

## 6. 校验 API

### 6.1 校验配置值（不保存）

`POST /api/v1/config/validate`

请求体包含配置键值对，返回：
- is_valid: 是否通过所有强制校验
- errors: 错误列表（类型错误、范围错误等）
- warnings: 警告列表（推荐范围超出等）
- conflicts: 冲突列表（互斥冲突、依赖缺失、逻辑不一致）

### 6.2 保存配置时的校验

`PUT /api/v1/config/values`

返回：
- success: 是否保存成功
- version: 新版本号
- validation: 校验结果（errors/warnings/conflicts）
- reload_required: 是否需要重启
- message: 提示信息

## 7. 前端校验集成

### 7.1 实时校验流程

1. 用户输入配置值
2. 前端 Layer 1 类型校验 → 失败则输入框变红 + 错误提示
3. 前端 Layer 2 范围校验 → 失败则输入框变红 + 错误提示
4. 前端 Layer 3 推荐范围校验 → 超出则输入框变黄 + 警告提示
5. 用户点击"保存"
6. 后端 Layer 1-4 完整校验
7. 如果有错误：返回错误列表，前端展示
8. 如果有警告：弹出确认框，展示警告信息
9. 如果无问题：保存配置，触发热重载

### 7.2 前端校验 Hook

前端提供 useConfigValidation hook，接收配置 key、当前值、元数据，返回校验状态（isValid, errors, warnings），在用户输入时实时触发校验。

---

## 8. 验收标准

| 验收项 | 标准 |
|--------|------|
| **类型校验** | 正确校验 float/int/bool/str/Dict/List 类型 |
| **范围校验** | 正确校验最小值、最大值、枚举值 |
| **推荐范围警告** | 超出推荐范围时展示警告，但不阻止保存 |
| **冲突检测** | 正确检测互斥配置、依赖缺失、逻辑不一致 |
| **前端实时校验** | 输入时实时校验，错误/警告展示正确 |
| **后端校验** | 保存时完整校验，返回错误/警告列表 |
| **性能** | 校验响应时间 < 100ms |
