# D-5: 输入校验与预处理

> **所属 Phase**: Phase D (P2)
> **任务类型**: 单一任务 — 查询入口的输入校验与预处理（空查询/超长查询/特殊字符）
> **对应问题**: 测试 10 部分问题（空查询、超长查询、特殊字符查询未处理）

## 🎯 目标

在 RAG 搜索入口处增加输入校验与预处理逻辑，确保异常查询不会导致系统崩溃或返回无意义结果。

## 📋 实施步骤

- [ ] **Step 1: 分析现有查询入口**
  - [ ] 阅读 `src/controller/rag_controller.py` 搜索端点
  - [ ] 阅读 `src/service/retrieval_service.py` 查询处理流程
  - [ ] 确认当前无输入校验的位置

- [ ] **Step 2: 实现输入校验规则**
  - [ ] 空查询：返回空结果 + 错误提示 "请输入搜索内容"
  - [ ] 超长查询（>200 字）：截断至 200 字 + 警告日志
  - [ ] 特殊字符：过滤 `!@#$%^&*()_+-=[]{}|;':",.<>/?` 等符号，保留中文、英文、数字
  - [ ] 纯空白字符：等同于空查询处理

- [ ] **Step 3: 实现超长查询意图提取**
  - [ ] 对于 50-200 字的超长查询，提取关键意图（前 50 字或关键词提取）
  - [ ] 使用提取的意图进行检索，原始查询用于后续展示
  - [ ] 添加日志记录原始查询与提取意图的差异

- [ ] **Step 4: 编写单元测试**
  - [ ] 测试空查询返回空结果
  - [ ] 测试超长查询截断与意图提取
  - [ ] 测试特殊字符过滤
  - [ ] 测试纯空白字符处理
  - [ ] 测试正常查询不受影响

- [ ] **Step 5: 集成验证**
  - [ ] 运行 `tests/diagnose_rag_comprehensive_v2.py` 测试 10 相关场景
  - [ ] 确认所有边界场景有合理处理

## ✅ 验收标准

| 场景 | 查询 | 期望行为 |
|------|------|----------|
| 空查询 | "" | 返回空结果 + 错误提示 |
| 超长查询 | "我有一个 3 岁的孩子..." (100+ 字) | 提取关键意图进行检索 |
| 特殊字符查询 | "感统训练！！！@@@###" | 过滤特殊字符后检索 |
| 纯空白 | "   " | 等同于空查询处理 |
| 正常查询 | "感统训练" | 不受影响 |

- 所有边界场景有合理的处理逻辑
- 正常查询不受影响
