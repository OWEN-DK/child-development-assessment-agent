# 多书籍 RAG 覆盖率与矛盾鉴别方案

> 日期: 2026-05-28 | 背景: 知识库书籍量增长，简单搜索覆盖面不足，书间存在矛盾

---

## 〇、现状分析

### 当前搜索链路

```
match_books_node
  ├── _analyze_and_search_books: 直接搜索知识库 → 候选书籍
  ├── _llm_match_books: 27B LLM 评估相关性 → matched_books
  └── search_book_ids: 所有候选书籍的 file_hash（不做过滤）

prefetch_context_node
  └── _do_prefetch: 社区树遍历 → knowledge_context（全局共享）

各节 _direct_search × 8 次
  ├── query: 原始 question + 前 10 词截断（仅 2 个变体）
  ├── limit: 15 条/次
  └── _format_search_context: top-15 × score 排序 → 截断至 10,000 字符
```

### 核心缺陷

| 维度 | 问题 | 代码位置 |
|------|------|---------|
| **搜索多样性** | 仅 2 个查询变体（原问题 + 前 10 词），图谱遍历深度不足 | `base.py:218-221` / `prefetch_context.py` |
| **结果截断** | 10,000 字符硬截断，多书时每本书只能分到零碎片段 | `base.py:289-307` |
| **书籍覆盖不均** | 无每书贡献度追踪，热门书淹没冷门书 | `_direct_search` 内部 |
| **无矛盾感知** | 即使两本书给出相反建议，LLM 也无从得知 | 全链路缺失 |
| **knowledge_context 单一** | 所有节共享同一份预取上下文，无节级定制 | `prefetch_context.py:21` |

## 一、覆盖率增强

### 1.1 知识图谱层级遍历增强 ✅ 已实施

**现状**: `prefetch_context_node` 通过社区树遍历预取知识上下文，`explore_community_tree`
使用 `max_tokens=12000` 控制遍历广度。遍历过程中收集的 `entity_names`（如"前庭觉失调"
"注意力不集中"）未在后续上下文构建中使用。

**方案**: 两处改动，不修改 `traversal.py` 接口，零侵入：

1. **扩大 token budget**：`max_tokens=24000`（2×），使遍历能覆盖更深层的关联社区
2. **实体名称嵌入上下文**：遍历结束后提取去重 `entity_names`，追加到 `knowledge_context`
   尾部作为关联实体提示——后续 section nodes 在 prompt 中使用 `knowledge_context` 时
   自然获得这些话题线索

**实施代码**：

\`\`\`python
# prefetch_context.py — _do_prefetch 内两处改动

# 改动 1: explore_community_tree 调用增加 max_tokens=24000
hits = await explore_community_tree(
    question=question,
    root_id=root.node_id,
    community_repo=community_repo,
    max_tokens=24000,  # 2× 默认值，更深遍历以覆盖更多关联实体
)

# 改动 2: knowledge_context 构建后追加 entity_names
if context:
    entity_names_set: set[str] = set()
    for hit in deduped:
        for name in (hit.entity_names or []):
            if name.strip():
                entity_names_set.add(name.strip())
    if entity_names_set:
        entity_hint = (
            "\n\n## 知识图谱关联实体\n"
            f"以下实体与问题相关，各节生成时可针对这些方向深入：\n"
            f"{', '.join(sorted(entity_names_set))}\n"
        )
        context += entity_hint
\`\`\`

**效果**：
- `max_tokens=24000`：遍历覆盖更深层社区，增加图谱命中量
- `entity_names` 嵌入：后续 S1-S5 各节的 prompt 中自动包含关联实体线索，
  无需修改任何 section node 代码
- 零侵入：`explore_community_tree` 原有接口不变

**改动量**: `prefetch_context.py` +18 行

### 1.2 配额制结果多样性（替代 MMR）

**现状**: 向量搜索结果按 score 降序排列，热门书垄断。

**方案**: 每本书最多 K 条结果配额，简单可预测。

```python
# nodes/base.py — _format_search_context 内，替代 sorted(results, key=score)

MAX_PER_BOOK = 5

def _diversify_by_quota(results: List[Dict], max_per_book: int = MAX_PER_BOOK) -> List[Dict]:
    """配额制多样性：每本书最多 max_per_book 条。

    比 MMR 更简单、可预测，不会出现同书第三条后 MMR 为负的极端情况。
    """
    selected: List[Dict] = []
    book_counts: Dict[str, int] = {}
    seen: set[str] = set()

    for r in sorted(results, key=lambda x: x.get("score", 0) or 0, reverse=True):
        cid = r.get("id") or r.get("chunk_id") or ""
        if cid in seen:
            continue
        source = _normalize_book_title(r.get("source_book", ""))
        if book_counts.get(source, 0) >= max_per_book:
            continue
        seen.add(cid)
        selected.append(r)
        book_counts[source] = book_counts.get(source, 0) + 1

    return selected
```

**效果**：
- 最多 5 本书时每本最多 5 条 = 25 条，覆盖均匀
- 10 本书时每本最多 5 条 = 50 条（前 50 条按 score 排序取，但每书不过 5）
- 100 本书时不会爆炸——limit=50-100 的原始搜索结果自然截断

**改动量**: `base.py` +15 行

## 二、矛盾鉴别 — 端到端数据流设计

### 2.1 设计目标

从"某观点来自哪本书"到"两本书观点冲突"，分 4 个阶段逐层推进，每阶段有可验证的 Gate。

当前数据流的缺口：

```
S2 ProblemItem:   {name, description, severity, category}
                  ❌ 无 source_books — 不知道问题从哪本书来

S3 ExerciseTypeItem: {type_id, name, tier, category, target_skills, rationale, citation_ids}
                      ❌ 无 source_books — 不知道推荐基于哪本书

KnowledgeQAState:    ❌ 无 contradictions 字段
KnowledgeQAResponse:  ❌ 无 contradictions 字段
```

### 2.2 数据流全景

```
Phase 1 (来源标注)           Phase 2 (矛盾审计)        Phase 3 (注入)          Phase 4 (导出)
┌──────────────────┐      ┌──────────────────┐      ┌──────────────────┐      ┌──────────────┐
│ 2.3 搜索结果加源标注 │ ───▶│ 2.7 审计节点      │ ───▶│ 2.8 S5 结论注入   │ ───▶│ 2.10 Markdown │
│ 2.4 S2/S3 加字段    │      │ 2.5 State 扩展    │      │ 2.9 前端 banner   │      │ 2.10 PDF 导出 │
│ 2.6 Prompt 要求     │      │ 2.5 Response 扩展 │      │                   │      │              │
└──────────────────┘      └──────────────────┘      └──────────────────┘      └──────────────┘
        │                        │
   Gate 1                    Gate 2
  source_books 填充率       矛盾检测准确率
      ≥ 60%                  召回 ≥ 70%
```

### 2.3 Phase 1.1: 搜索结果加源标注

**位置**: \`nodes/base.py:277\` — \`_format_search_context\`

在每条搜索结果前加 \`📖 {book_title}\` 前缀，按书籍分组展示。LLM 在阅读搜索上下文时能直观区分每段内容来自哪本书——这是后续所有 \`source_books\` 标注的基础。

```python
# base.py _format_search_context — 按书籍分组，显式标注来源

def _format_search_context(results: List[Dict]) -> str:
    if not results:
        return "（未搜索到相关内容）"

    seen: set[str] = set()
    by_book: Dict[str, List[Dict]] = {}
    for r in sorted(results, key=lambda x: x.get("score", 0) or 0, reverse=True):
        cid = r.get("id") or r.get("chunk_id") or ""
        if cid in seen:
            continue
        seen.add(cid)
        source = _normalize_book_title(r.get("source_book", ""))
        by_book.setdefault(source, []).append(r)

    parts: List[str] = []
    for book_title, items in by_book.items():
        parts.append(f"
### 📖 {book_title}（{len(items)} 条）
")
        for r in items:
            chapter = r.get("chapter_title", "未知")
            parts.append(
                f"> **{chapter}**
"
                f"> {r.get('content', '')[:300]}
"
            )

    parts.append(
        "
> ⚠️ 引用提示：当不同书籍对同一问题有不同观点时，请分别引用并标注来源书籍。"
    )
    return "
".join(parts)
```

```python
async def contradiction_audit_node(state: KnowledgeQAState) -> Dict[str, Any]:
    """从 S2/S3 structured_data 提取带 source_books 的声明，LLM 检测跨书籍矛盾。

    降级路径:
      1. claims < 2 → 返回空（无足够多来源数据审计）
      2. LLM 调用失败 → 返回空（不阻塞主流程）
    """
    await push_progress("contradiction_audit", "正在审计跨书籍观点一致性…")

    # Step 1: 提取带来源标注的声明
    claims = _extract_sourced_claims(state)

    if len(claims) < 2:
        await push_progress("contradiction_audit_done", "未发现足够的多来源声明")
        return {"contradictions": [], "current_step": ["contradiction_audit_clean"]}

    # Step 2: LLM 审计
    prompt = _build_contradiction_prompt(state.question, claims, state.matched_books_detail)
    try:
        result = await _invoke_llm_structured(
            system_prompt=CONTRADICTION_AUDIT_SYSTEM,
            user_message=prompt,
            response_format=ContradictionAuditResponse,
            step_label="contradiction_audit",
            timeout_seconds=30,
        )
    except Exception as e:
        logger.warning(f"contradiction_audit LLM 调用失败: {e}")
        return {"contradictions": [], "current_step": ["contradiction_audit_failed"]}

    await push_progress(
        "contradiction_audit_done",
        f"矛盾审计完成：发现 {len(result.contradictions)} 处潜在矛盾",
    )
    return {
        "contradictions": [c.model_dump() for c in result.contradictions],
        "current_step": ["contradiction_audit_done"],
    }


def _extract_sourced_claims(state: KnowledgeQAState) -> List[Dict]:
    """从 S2/S3 structured_data 提取带 source_books 的声明。
    只提取至少有 1 个 source_book 的条目——否则无法判断矛盾。
    """
    claims = []

    # S2: problems
    s2 = state.sections.get(2)
    if s2 and s2.structured_data:
        for p in (s2.structured_data.get("problems") or []):
            source_books = p.get("source_books", [])
            if source_books:
                claims.append({
                    "section": 2,
                    "topic": p.get("name") or p.get("description", ""),
                    "detail": p.get("description", ""),
                    "severity": p.get("severity", ""),
                    "source_books": source_books,
                })

    # S3: exercise_types
    s3 = state.sections.get(3)
    if s3 and s3.structured_data:
        for et in (s3.structured_data.get("exercise_types") or []):
            source_books = et.get("source_books", [])
            if source_books:
                claims.append({
                    "section": 3,
                    "topic": et.get("name", ""),
                    "detail": et.get("recommendation_rationale", ""),
                    "tier": et.get("tier", ""),
                    "source_books": source_books,
                })

    return claims
```
