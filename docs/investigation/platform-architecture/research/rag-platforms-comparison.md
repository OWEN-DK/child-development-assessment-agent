# RAG 平台竞品对比

为了明确本方案"配置驱动的客户交付平台"定位，我们选取了当前 RAG 平台领域最具代表性的三个项目（Dify、LangFlow、RAGFlow）与项目目标架构进行七维度对比。对比聚焦于：管道构建方式、业务与平台的解耦程度、增强节点体系、多客户交付模式、后端技术选型与部署形态。

| | Dify | LangFlow | RAGFlow | 本方案 |
|---|---|---|---|---|
| **定位** | 开发者自建 RAG 应用 | 开发者 RAG IDE | 企业检索平台 | **客户交付平台** |
| **管道构建** | 可视化 Knowledge Pipeline | 可视化 LangChain | 可视化工作流 | 可视化管道构建器 |
| **配置驱动业务** | ❌ 代码驱动 | ❌ 代码驱动 | 部分（YAML） | **✅ 核心设计** |
| **增强节点体系** | 弱（少量内置） | 弱（依赖 LangChain） | 中（检索增强为主） | **✅ 一等公民** |
| **多客户实例** | 应用级隔离 | 应用级隔离 | 应用级隔离 | **管道配置级隔离** |
| **后端语言** | Python | Python | C++/Python | **Python（一期）** |
| **独立部署** | Docker | Docker | Docker | **Docker** |

差异化总结：竞品面向"开发者自建 RAG 应用"场景，业务逻辑与平台代码耦合在应用层级。本方案面向"交付多个客户"场景，核心设计在于一条管道配置等于一个完整业务——客户之间通过管道配置级隔离，新增客户仅需新增一个 JSON 文件，不需要修改平台代码。
