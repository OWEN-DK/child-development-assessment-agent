> **版本**: v1.1

> **状态**: ✅ 已实施（待集成验证）  
> **关联**: `07-知识图谱直提方案-D2G.md`  
> **问题**: 质量审计报告 — 孤立实体率 72%、平均度 0.6、最大连通分量 8.1%

### 1.2 根因分析

#### 根因 1：并发提取导致跨章关系机制形同虚设（致命）
`book_pipeline.py` 中所有章节通过 `asyncio.gather` 并行提取。`_get_existing_entities(state)` 始终返回空。

#### 根因 2：两步提取导致实体-关系脱节
Round 1 提实体 → Round 2 提关系，LLM 注意力前向，容易遗漏。

#### 根因 3：关系提取 Prompt 要求"推理"而非"抽取"
40 种关系类型是巨大认知负担。

#### 根因 4：无后验补全机制
提取完直接入图，无检查-补全循环。

#### 根因 5：无规则层兜底
完全依赖 LLM，无领域规则。

## 2. 实施方案

### 2.1 总体架构

```
Phase 0: 全书阅读（不变）
    │
    ▼
Phase 1: 逐章联合提取（改造）
    │  Round 1: 单 Pass 实体+关系联合提取
    │  Round 2: 覆盖度自检 + 孤立实体定向补全
    │  Round 3: 细节提取
    │  处理模式: 串行
    │
    ▼
Phase 2: 审核 + 消歧 + 合入主图（不变）
    │
    ▼
Phase 2.5: 全局关系补全（新增）
    │  Step 1: 类型规则推断（零 LLM 成本）
    │  Step 2: Embedding 语义关联（低成本）
    │  Step 3: LLM 全局孤立实体补全（兜底）
    │
    ▼
Phase 3: 质量审计（增加来源分析）
Phase 4: 入库（不变）
```
