## 1. 问题背景与设计约束

### 1.1 当前方案的不足

| # | 问题 | 影响 |
|---|------|------|
| 1 | **流程错位**：`bind_book` 是第一步，但用户期望"审核完毕后再入库" | 绑定了但内容未审核，语义混乱 |
| 2 | **Phase 5 时机错误**：在 `publish_to_neo4j` 之后执行，审核者无法介入 | 误合并无法在审核阶段修正 |
| 3 | **只做实体消歧**：仅有 SAME_AS/合并，缺少跨书语义关系发现 | 两本书的知识无法编织成更大的网络 |
| 4 | **跨书关系类型单一**：`cross_relation.py` 仅支持 CONSENSUS/COMPLEMENTS/CONFLICTS | 无法表达"书1的方案治疗书2的问题"这类知识连接 |
| 5 | **删除不彻底**：`deleteBook` 只删元数据，Neo4j 残留实体 | 重新绑定时旧数据干扰融合 |
| 6 | **无类型感知**：Problem 和 Exercise 也做 Embedding 比较 | 大量无意义比较，误合并风险高 |

### 1.2 设计约束（用户明确要求）

| 约束 | 说明 |
|------|------|
| **逐本绑定** | 一次只绑定一本书，不存在批量绑定或多用户同时绑定 |
| **支持删除重绑** | 用户可能删除一本书后重新绑定，需彻底清理 |
| **审核在先** | 用户需要审核和修改 AI 生成内容后，才执行入库和跨书融合 |
| **草稿阶段即融合** | 跨书匹配在草稿阶段就开始，审核者能看到并做决策 |
| **不只是 SAME_AS** | 跨书关系包括实体消歧 + 语义关系发现（TREATS, CAUSES, IMPROVES...） |

## 3. 实体消歧（SAME_AS）改进

### 3.1 类型感知匹配

**核心改进**：只在相同 `entity_type` 内做比较。

```python
# 改进前：全量笛卡尔积
for new_e in new_entities:
    for other_e in other_entities:  # 所有类型混在一起
        sim = cosine(new_e.emb, other_e.emb)

# 改进后：按类型分组
from collections import defaultdict
type_groups = defaultdict(list)
for e in other_entities:
    type_groups[e.entity_type].append(e)

for new_e in new_entities:
    candidates = type_groups.get(new_e.entity_type, [])
    for other_e in candidates:  # 只比较同类型
        sim = cosine(new_e.emb, other_e.emb)
```

**收益**：
- 比较量从 $O(N \times M)$ 降到 $O(N \times M / T)$（T=类型数，当前 27 种）
- 消除最大误合并来源（Problem vs Exercise）

### 3.2 分层阈值（沿用 v1，微调）

| 相似度范围 | 判定 | 执行动作 | 前置条件 |
|-----------|------|---------|---------|
| ≥ 0.9 | 高度相似 | **合并**（需审核者确认或高置信度） | 同类型 |
| 0.7 ~ 0.9 | 中度相似 | 创建 **SAME_AS** 边 | 同类型 |
| < 0.7 | 低相似度 | **不处理** | — |
| 名称精确匹配 | 完全一致 | **直接合并**（跳过 LLM） | 同类型 |
| 括号别名匹配 | 包含关系 | 相似度设为 0.85 | 同类型 |

### 3.4 图结构特征（辅助信号）

在 LLM Prompt 中加入实体的**关系邻居**，让 LLM 利用图结构做判断。

```python
def _get_entity_neighbors(entity_name: str, book_id: str, neo4j_session) -> list[dict]:
    """获取实体的关系邻居（入边+出边，取 Top 10）。"""
    result = neo4j_session.run("""
        MATCH (n {name: $name})
        WHERE $book_id IN coalesce(n.book_ids, [n.book_id])
        OPTIONAL MATCH (n)-[r]->(m)
        RETURN 'out' AS dir, type(r) AS rel, m.name AS neighbor, labels(m)[0] AS ntype
        UNION ALL
        MATCH (n {name: $name})
        WHERE $book_id IN coalesce(n.book_ids, [n.book_id])
        OPTIONAL MATCH (m)-[r]->(n)
        RETURN 'in' AS dir, type(r) AS rel, m.name AS neighbor, labels(m)[0] AS ntype
        LIMIT 10
    """, name=entity_name, book_id=book_id).data()
    return result
```

## 4. 跨书语义关系发现（全新）

### 4.1 问题定义

实体消歧只解决"同一实体在不同书中的对齐"。但更大的价值在于发现**不同实体之间的知识连接**：

```
书1: "有氧运动" (Exercise) — 每天30分钟
书2: "ADHD" (Problem) — 注意力缺陷

→ 跨书关系: 有氧运动 TREATS ADHD
```

```
书1: "前额叶皮层" (BrainRegion) — 执行功能核心脑区
书2: "工作记忆训练" (Solution) — 改善执行功能

→ 跨书关系: 工作记忆训练 IMPROVES 前额叶皮层功能
```

```
书1: "BDNF 分泌不足" (RootCause) — 与注意力缺陷相关
书2: "跑步" (Exercise) — 促进 BDNF 分泌

→ 跨书关系: 跑步 ADDRESSES BDNF 分泌不足
```

### 4.2 跨书关系类型体系

在现有单书关系类型（§schema.py）基础上，扩展跨书语义关系：

| 关系大类 | 关系类型 | 说明 | 示例 |
|---------|---------|------|------|
| **治疗/干预** | `CROSS_TREATS` | 书A的方案治疗书B的问题 | 跑步 TREATS ADHD |
| | `CROSS_PREVENTS` | 书A的方案预防书B的风险 | 有氧运动 PREVENTS 肥胖风险 |
| | `CROSS_ALLEVIATES` | 书A的方案缓解书B的症状 | 冥想 ALLEVIATES 焦虑 |
| **因果/机制** | `CROSS_CAUSES` | 书A的根因导致书B的问题 | BDNF不足 CAUSES 注意力缺陷 |
| | `CROSS_CONTRIBUTES_TO` | 书A的因素促成书B | 睡眠不足 CONTRIBUTES_TO 多动 |
| **改善/增强** | `CROSS_IMPROVES` | 书A的方案改善书B的功能 | 跑步 IMPROVES 前额叶功能 |
| | `CROSS_ENHANCES` | 书A的方案增强书B | 有氧运动 ENHANCES BDNF分泌 |
| **理论/证据** | `CROSS_SUPPORTS` | 书A的研究支持书B的理论 | fMRI研究 SUPPORTS 感觉统合理论 |
| | `CROSS_CONTRADICTS` | 书A的发现与书B矛盾 | 新研究 CONTRADICTS 旧理论 |
| | `CROSS_EXTENDS` | 书A扩展了书B的概念 | 书A的干预策略 EXTENDS 书B的理论框架 |
| **组成/分类** | `CROSS_PART_OF` | 书A的实体是书B概念的一部分 | 注意力训练 PART_OF 认知干预体系 |
| **互补** | `CROSS_COMPLEMENTS` | 两书内容互补 | 书A讲理论，书B讲实践方法 |

### 4.3 发现算法：三阶段流水线

```
Stage 1: 候选对生成（粗筛）
  ├── 同类型实体对 → 走实体消歧（§3）
  └── 不同类型但有语义关联的实体对 → 进入关系发现

Stage 2: 关系候选筛选（Embedding + 规则）
  ├── 规则预筛：按类型组合过滤（Problem×Solution, RootCause×Exercise...）
  ├── Embedding 相似度：名称+描述的语义距离
  └── 图结构信号：已有关系的邻居是否有重叠

Stage 3: LLM 关系判定（精判）
  ├── 批量判定：每批 5-10 对，一次 LLM 调用
  ├── 输出：关系类型 + 置信度 + 理由
  └── 置信度 < 0.5 的直接丢弃
```

### 4.6 候选对生成策略

全量类型组合的笛卡尔积太大。采用**两步筛选**：

**Step 1: 类型组合过滤**（§4.4 矩阵）→ 从 $O(N \times M)$ 降到有效组合

**Step 2: Embedding 粗筛**（同类型内已做，跨类型也需要）

```python
async def _find_cross_relation_candidates(
    new_entities: list[EntityCandidate],
    other_entities: list[EntityCandidate],
    embedding_helper,
) -> list[tuple[EntityCandidate, EntityCandidate, float]]:
    """找到跨类型的语义关系候选对。"""
    valid_combos = {(src, tgt) for src, tgt, _ in CROSS_RELATION_TYPE_COMBOS}
    
    candidates = []
    for new_e in new_entities:
        for other_e in other_entities:
            # 同类型走实体消歧，跳过
            if new_e.entity_type == other_e.entity_type:
                continue
            # 类型组合过滤
            combo = (new_e.entity_type, other_e.entity_type)
            combo_rev = (other_e.entity_type, new_e.entity_type)
            if combo not in valid_combos and combo_rev not in valid_combos:
                continue
            # Embedding 粗筛
            sim = embedding_helper.cosine_similarity(
                new_e.embedding, other_e.embedding
            )
            if sim >= 0.5:  # 跨类型阈值较低，留给 LLM 精判
                candidates.append((new_e, other_e, sim))
    
    return candidates
```

async def commit_to_graph(draft_id: str) -> APIResponse:

    5. 解析审核者决策
    6. 执行 Phase 5b（合并/建边/跨书关系）
    7. 全局图重建

    9. 更新状态为 "published"

    book_id = get_book_id_from_draft(draft_id)

    from src.core.knowledge_qa.neo4j.driver import get_async_neo4j_driver

    with neo4j_driver.session() as session:
        # 移除 staging label，清理临时属性

            MATCH (n:D2G_Staging {book_id: $book_id})
            REMOVE n:D2G_Staging
            REMOVE n.extraction_version
        """, book_id=book_id)
    
    # ── Step 2: 清理 staging 残留数据 ──
    # 确保没有任何 staging 节点残留（防御性清理）
    with neo4j_driver.session() as session:
        result = session.run("""
            MATCH (n:D2G_Staging {book_id: $book_id})
            DETACH DELETE n
            RETURN count(n) AS cleaned

            logger.warning("清理了 %d 个残留 staging 节点 book_id=%s", cleaned, book_id)
    
    # ── Step 3: 执行 Phase 5b 跨书融合决策 ──

            if success:
                outcome.merged_count += 1
        elif match.reviewer_decision == "separate":
            outcome.separated_count += 1
        elif match.reviewer_decision == "auto":
            # 委托系统自动处理（审核者明确选择"自动"）
            # 委托系统自动处理（审核者明确选择"自动"）
            if match.similarity >= 0.9 and match.llm_same:
                execute_entity_merge(match, neo4j_driver)
                outcome.auto_merged_count += 1
            elif match.similarity >= 0.7 and match.llm_same:
                create_same_as_edge(match, neo4j_driver)
                outcome.same_as_count += 1
        elif match.reviewer_decision == "skip":
            # 审核者明确跳过（不处理）
            outcome.skipped_count += 1

        if rel.reviewer_decision == "confirm":
            create_cross_book_relation(rel, neo4j_driver)

        elif rel.reviewer_decision == "modify" and rel.custom_type:
            rel.relation_type = rel.custom_type
            create_cross_book_relation(rel, neo4j_driver)
            outcome.relations_created += 1
        elif rel.reviewer_decision == "auto":

            if rel.confidence >= 0.85:

## 7. 删除与重绑

### 7.1 核心原则

> **删除一本书后，其他书的数据不受影响，但该书与其他书之间的所有关系（SAME_AS、CROSS_*、MergeLog）全部清除。**

### 7.2 删除场景分析

假设当前有书1和书2，用户删除书2：

```
删除前:
  书1独有实体: A1, A2
  书2独有实体: B1, B2
  合并实体: M1 (原书1的A3 + 书2的B3 合并而来, book_ids=["book1","book2"])
  关系:
    A1 -[THERAPEUTIC_TREATS]-> A2      (书1内部)
    B1 -[CAUSAL_CAUSES]-> B2           (书2内部)
    M1 -[FUNCTIONAL_REGULATES]-> A1    (合并后的关系)
    M1 -[CROSS_TREATS]-> B1            (跨书语义关系)
    A1 -[SAME_AS]-> B1                 (跨书同义边，如果存在)

删除后:
  书1独有实体: A1, A2           ← 不动
  合并实体: M1                  ← 保留，但 book_ids=["book1"]
  关系:
    A1 -[THERAPEUTIC_TREATS]-> A2      ← 保留
    M1 -[FUNCTIONAL_REGULATES]-> A1    ← 保留（M1 仍属于书1）
  被删除的:
    B1, B2 (节点 + 所有关系)           ← 整体删除
    M1 -[CROSS_TREATS]-> B1            ← B1 被删，关系随之消失
    A1 -[SAME_AS]-> B1                 ← B1 被删，关系随之消失
    MergeLog (记录书2→书1的合并历史)     ← 清理
```

### 7.3 删除执行流程

### 7.4 Neo4j 清理 Cypher（完整版）

```cypher
// ============================================================
// Step 1: 删除该书独有的实体节点（未被合并的）
// 这些节点的 book_ids 只包含被删除的书
// DETACH DELETE 会同时删除节点和它所有的入边/出边
// ============================================================
MATCH (n)
WHERE $book_id IN coalesce(n.book_ids, [n.book_id])
  AND size(coalesce(n.book_ids, [n.book_id])) = 1
  AND NOT n:Book
  AND NOT n:MergeLog
DETACH DELETE n

// ============================================================
// Step 2: 对于合并实体，从 book_ids 中移除该书
// 这些节点属于多本书，删除其中一本后节点保留
// ============================================================
MATCH (n)
WHERE $book_id IN coalesce(n.book_ids, [n.book_id])
  AND size(coalesce(n.book_ids, [n.book_id])) > 1
SET n.book_ids = [bid IN coalesce(n.book_ids, [n.book_id]) WHERE bid <> $book_id]

// 如果 book_id 恰好是被删除的书，重新赋值为 book_ids 中的第一个
MATCH (n)
WHERE n.book_id = $book_id AND exists(n.book_ids) AND size(n.book_ids) > 0
SET n.book_id = n.book_ids[0]

// ============================================================
// Step 3: 删除该书相关的跨书关系边
// 包括 SAME_AS 和所有 CROSS_* 语义关系
// 这些边通过 source_book / target_book 属性标记来源
// ============================================================
MATCH (a)-[r]->(b)
WHERE (
    r.source_book = $book_id OR r.target_book = $book_id
  )
  AND (
    type(r) = 'SAME_AS'
    OR type(r) STARTS WITH 'CROSS_'
  )
DELETE r

// ============================================================
// Step 4: 清理 MergeLog 节点
// 情况 A: MergeLog 记录了该书实体被合并到其他书 → 删除日志和 MERGED_FROM 边
// 情况 B: MergeLog 记录了其他书实体被合并到该书 → 同样清理
// ============================================================
// 情况 A: 该书实体是合并的"来源"（source_book_id = 被删除的书）
MATCH (target)-[r:MERGED_FROM]->(log:MergeLog)
WHERE log.source_book_id = $book_id
DELETE r, log

// 情况 B: 该书实体是合并的"目标"（合并到该书的实体）
MATCH (n)-[r:MERGED_FROM]->(log:MergeLog)
WHERE $book_id IN coalesce(n.book_ids, [n.book_id])
  AND log.target_entity IN [m.name IN labels(n)]
DELETE r
// 注意：情况 B 的节点已在 Step 2 中处理 book_ids，
// 但 MergeLog 本身需要清理

// ============================================================
// Step 5: 删除该书的 Book 节点
// ============================================================
MATCH (b:Book {book_id: $book_id})
DETACH DELETE b
```

### 7.5 关键边界情况

| 情况 | 处理方式 | 说明 |
|------|---------|------|
| 书2独有实体 B1 有内部关系 B1→B2 | Step 1 DETACH DELETE 自动删除 | B1、B2 都是独有节点，一起删 |
| 合并实体 M1 有关系 M1→A1（A1 属于书1） | Step 2 只改 book_ids，关系保留 | M1 仍属于书1，关系不动 |
| 合并实体 M1 有关系 M1→B1（B1 属于书2） | Step 1 删除 B1 时，M1→B1 关系随之消失 | DETACH DELETE 的级联效果 |
| A1↔B1 的 SAME_AS 边 | Step 3 删除 | 跨书关系全部清除 |
| A1→B1 的 CROSS_TREATS 边 | Step 3 删除 | 跨书关系全部清除 |
| M1 的 MergeLog（记录 B3→A3 合并） | Step 4 清理 | 合并历史不再有意义 |
| 删除书2后 M1 的 book_ids | ["book1"] | Step 2 处理 |

### 7.6 重绑流程

删除后重新绑定书2，系统将其视为**全新书籍**：

```
删除书2 → 彻底清理书2的所有数据
重新绑定书2 → 完整走一遍 Phase 0-4 + Phase 5a + 审核 + Phase 5b
```

**注意事项**：
- 如果书2之前与书1有合并关系，删除书2时合并实体保留（归书1），但 book_ids 中移除书2
- 重新绑定后，Phase 5a 会重新检测书2新实体与书1实体的跨书匹配
- 审核者需要重新确认决策（之前的决策已随 Redis 清理而消失）
- 如果重新绑定的书2内容与之前相同，可能会重新发现相同的合并/关系，这是预期行为

| Key | 说明 | TTL | 主动清理时机 |
|-----|------|-----|-------------|
| `d2g:cross_analysis:{book_id}` | Phase 5a 分析结果 | 7 天 | 入库完成时 / 删除书籍时 |
| `d2g:cross_decisions:{book_id}` | 审核者决策（前端实时更新） | 7 天 | 入库完成时 / 删除书籍时 |
| `d2g:cross_result:{book_id}` | Phase 5b 执行结果（审计用） | 30 天 | 删除书籍时 |
| `d2g:master_graph:{book_id}` | Phase 2 内存主图暂存 | 1 天 | Phase 4 入库完成后 |
| `d2g:progress:{book_id}` | 生成进度 SSE 状态 | 1 天 | 生成完成/失败后 |

**清理原则**：
- **TTL 兜底**：所有 Key 必须设置 TTL，防止因程序异常导致永久残留
- **主动清理**：在业务流程的关键节点（入库完成、删除书籍）主动 `DEL`
- **双保险**：TTL + 主动清理，两者缺一不可

**清理代码**：

```python
def cleanup_redis_for_book(book_id: str) -> None:
    """清理指定书籍的所有 Redis 暂存数据。"""
    keys = [
        f"d2g:cross_analysis:{book_id}",
        f"d2g:cross_decisions:{book_id}",
        f"d2g:cross_result:{book_id}",
        f"d2g:master_graph:{book_id}",
        f"d2g:progress:{book_id}",
    ]
    for key in keys:
        redis_client.delete(key)
    logger.info("Redis 暂存数据已清理: book_id=%s", book_id)
```

**调用时机**：
1. `commit_to_graph()` 入库完成时 → 清理 analysis + decisions + master_graph + progress
2. `delete_book()` 删除书籍时 → 清理全部 5 类 Key
3. 生成任务失败/取消时 → 清理 master_graph + progress

**API 批量接口**：

```python
@router.post("/api/v2/curation/cross-book/decision/batch")
async def batch_update_decisions(
    book_id: str,
    decision_type: str,      # "entity_match" / "cross_relation"
    indices: list[int],       # 要操作的条目索引列表
    decision: str,            # 统一决策
):
    # 批量更新 JSON 文件中的 reviewer_decision 字段
    data = load_cross_book_json(book_id)
    target = data["entity_matches"] if decision_type == "entity_match" else data["cross_relations"]
    for item in target:
        if item["index"] in indices:
            item["reviewer_decision"] = decision
    save_cross_book_json(book_id, data)
```
