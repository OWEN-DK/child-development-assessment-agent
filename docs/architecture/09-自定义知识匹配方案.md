# 自定义知识匹配方案 — 高优先级非书籍知识源 + 三层知识综合

> **版本**: v3.1  
> **日期**: 2026-05-31（v3.1 跨文档一致性审核修复）  
> **状态**: ✅ 已审核（v3.1 修复跨文档一致性问题）  
> **依赖**: [07-知识图谱直提方案-D2G.md](07-知识图谱直提方案-D2G.md)、[08-知识图谱多书扩展方案.md](08-知识图谱多书扩展方案.md)  
> **目的**:  
> 1. 支持非书籍来源的高优先级知识（专家经验、临床指南等），引导 D2G/LazyGraphRAG 搜索方向  
> 2. 实现三层知识综合框架（统一共识 / 互补完善 / 冲突辨析）

---

## 1. 问题背景

### 1.1 当前知识问答的知识来源

```
match_books → query_neo4j_graph → prefetch_context → S1→S2→S3→S4→conclusion→finalize
               (D2G/Neo4j)        (LazyGraphRAG)
```

两条知识源均来自**书籍**，无法引入外部专家知识。

### 1.2 缺失的能力

| # | 需求 | 现状 |
|---|------|------|
| 1 | 非书籍知识来源（专家经验、临床指南） | 所有知识需通过书籍导入流程入库 |
| 2 | 高于 D2G 的优先级 | 知识源无优先级概念 |
| 3 | 跨书知识综合（共识/互补/冲突） | 仅 `contradiction_audit_v2` 处理冲突，共识和互补未使用 |
| 4 | 动态知识管理 | 知识入库需走完整 EPUB→图谱 流程 |

### 1.3 目标架构

```
用户问题
    │
    ▼
match_books（不变）
    │
    ▼
fast_knowledge_match [新增] ← 自定义知识三通道匹配
    │  命中 → 注入 custom_knowledge_context + entities
    │  未命中 → 无注入
    │
    ▼ (无论命中与否)
query_neo4j_graph ← 用 custom_knowledge_entities 增强查询
    │
    ▼
prefetch_context ← 用 custom_knowledge_entities 增强遍历
    │
    ▼
S1→S2→S3→S4（三层知识注入: 自定义 > D2G > LazyGraphRAG）
    │
    ▼
knowledge_synthesis_v2 [新增] ← 三层综合: 共识/互补/冲突
    │
    ▼
conclusion → finalize → END
```

## 2. 存储方案

### 2.1 Neo4j 原生存储

自定义知识以 `CustomRule` 节点形式存入 Neo4j，与书籍知识共享图谱。

**节点类型**: `CustomRule`

| 属性 | 类型 | 说明 |
|------|------|------|
| `rule_id` | string | 业务 ID（`cr_` + 序号） |
| `title` | string | 知识标题 |
| `content` | string | 知识正文（Markdown） |
| `category` | string | `expert_rule` / `clinical_guideline` / `policy` / `faq` / `general` |
| `priority` | int | 优先级（数值越大越优先） |
| `enabled` | bool | 启停控制 |
| `source` | string | 来源标注 |
| `match_count` | int | 累计命中次数 |
| `embedding` | list[float] | 语义向量（1536 维） |

**关系类型**:

| 关系 | 方向 | 含义 |
|------|------|------|
| `OVERRIDES` | CustomRule → 实体 | 纠正/覆盖 |
| `ENHANCES` | CustomRule → 实体 | 补充细节 |
| `RELATES_TO` | CustomRule → 实体 | 关联 |
| `SUPPLEMENTS` | CustomRule → Book | 补充书籍知识 |

### 2.2 MySQL 辅助索引

快速匹配仍需 MySQL 索引（Neo4j 不擅长关键词/正则/向量匹配）。

```sql
CREATE TABLE custom_knowledge_index (
    rule_id         VARCHAR(32) PRIMARY KEY COMMENT '对应 Neo4j CustomRule.rule_id',
    keywords        JSON COMMENT '精确匹配关键词',
    trigger_patterns JSON COMMENT '正则触发模式',
    embedding       JSON COMMENT '语义向量',
    priority        INT NOT NULL DEFAULT 100,
    enabled         TINYINT(1) NOT NULL DEFAULT 1,
    updated_at      DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_cki_priority (priority),
    INDEX idx_cki_enabled (enabled)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**双写**: 创建/更新/删除时同时操作 Neo4j + MySQL。Neo4j 是真相源。

## 3. 数据流设计

### 3.1 核心原则

> **自定义知识是"主干"，D2G/LazyGraphRAG 是"补充"。三者都参与，自定义知识引导搜索方向。**

不短路的原因: 自定义知识可能只覆盖问题的某个方面，跳过 D2G/LazyGraphRAG 会导致回答片面。

### 3.2 State 字段

```python
# 新增字段
custom_knowledge_context: str = ""          # 自定义知识 Markdown（最高优先级）
custom_knowledge_entities: List[str] = []   # 关键实体名（引导下游搜索）
fast_knowledge_hit: bool = False            # 是否命中
three_layer_synthesis: Dict[str, Any] = {}  # 三层综合结果
```

**关键**: 自定义知识注入 `custom_knowledge_context`（新字段），**不注入** `knowledge_context`（现有字段），避免 `prefetch_context_node` 跳过。

### 3.3 逐节点数据流

#### fast_knowledge_match_node

```
输入: state.question
  │
  ▼ MySQL 三通道匹配（关键词→正则→语义）
  │
  ├─ 命中:
  │   ① Neo4j 取 CustomRule 完整节点 + 关联实体
  │   ② 格式化 → custom_knowledge_context
  │   ③ 提取关键实体 → custom_knowledge_entities
  │   ④ fast_knowledge_hit = True
  │
  └─ 未命中: fast_knowledge_hit = False
```

#### query_neo4j_graph_node（修改）

```
现有: s2_problems 来自 S2 识别的问题
增强: s2_problems += custom_knowledge_entities
效果: Neo4j 查询范围扩大，命中更多相关实体
```

#### prefetch_context_node（修改）

```
现有: if state.knowledge_context: return skip  ← 必须删除
增强: enhanced_q = question + " " + " ".join(custom_knowledge_entities)
效果: 向量种子更精准，命中更多相关社区
```

#### S1-S4 节点（修改 _build_full_user_message）

```
注入顺序（优先级从高到低）:
  ① custom_knowledge_context ← 最高优先级
  ② neo4j_knowledge (D2G)
  ③ knowledge_context (LazyGraphRAG)
  ④ exercise_context (权威运动清单)
```

#### knowledge_synthesis_v2_node（新增，替代 contradiction_audit_v2）

```
输入: neo4j_knowledge.cross_book_relations + S1-S4 内容
  │
  ├─ Neo4j 有跨书关系:
  │   CONSENSUS → consensus 层
  │   COMPLEMENTS → complementary 层
  │   CONFLICTS → conflicts 层
  │
  └─ Neo4j 无跨书关系（单书场景）:
      LLM 从前 4 节内容推断三层

输出: three_layer_synthesis + contradictions（兼容）
```

#### conclusion_node（修改）

```
现有: 仅注入 contradictions
增强: 注入 three_layer_synthesis 三层:
  ✅ 统一共识 → "所有书认同: ..."
  🧩 互补完善 → "A说机制，B说方案 → 综合: ..."
  ⚠️ 冲突辨析 → "A说高强度，B说中强度 → 原因: ... → 建议: ..."
```

## 4. 三通道匹配引擎

### 4.1 匹配流程

```
用户问题
    │
    ▼
通道 1: 关键词精确匹配（<1ms）
    │ question.lower() 包含任一 keyword
    ├─ 命中 → 取 Neo4j CustomRule
    │
    ▼ 未命中
通道 2: 正则模式匹配（<5ms）
    │ re.search(pattern, question)
    ├─ 命中 → 取 Neo4j CustomRule
    │
    ▼ 未命中
通道 3: 语义向量匹配（~200ms）
    │ cosine(question_embedding, item.embedding) >= 0.80
    ├─ 命中 → 取 Neo4j CustomRule
    │
    ▼ 未命中
继续 D2G/LazyGraphRAG（无自定义知识注入）
```

### 4.2 命中后处理

```
1. Neo4j: 取 CustomRule 完整节点 + 关联实体
2. 构造 custom_knowledge_context (Markdown)
3. 提取 custom_knowledge_entities (列表)
4. 更新 match_count
```

## 5. 三层知识综合框架

### 5.1 数据来源

**主要**: Neo4j 跨书关系（已有但未充分利用）

| 关系类型 | 当前使用 | 本方案使用 |
|---------|---------|-----------|
| `CROSS_BOOK_CONSENSUS` | ❌ 未使用 | ✅ 统一共识层 |
| `CROSS_BOOK_COMPLEMENTS` | ❌ 未使用 | ✅ 互补完善层 |
| `CROSS_BOOK_CONFLICTS` | ✅ contradiction_audit | ✅ 冲突辨析层（增强） |

**降级**: 单书场景或 Neo4j 数据不足时，LLM 从前 4 节内容推断。

### 5.2 各层数据结构与呈现

#### 统一共识层 (consensus)

```json
{
    "topic": "有氧运动对 ADHD 的改善效果",
    "agreement": "所有书籍均认同: 每周 3-5 次有氧运动可改善注意力",
    "confidence": "high",
    "sources": ["运动改变大脑", "儿童运动处方"]
}
```

呈现:
```markdown
## ✅ 统一共识（高置信度）
**有氧运动对 ADHD 的改善效果**
所有书籍均认同: 每周 3-5 次有氧运动可改善注意力。
📖 来源: 《运动改变大脑》《儿童运动处方》
```

#### 互补完善层 (complementary)

```json
{
    "topic": "ADHD 运动干预的完整体系",
    "fragments": [
        {"book": "运动改变大脑", "perspective": "神经科学机制"},
        {"book": "儿童运动处方", "perspective": "具体运动方案"},
        {"book": "儿童发展心理学", "perspective": "行为管理"}
    ],
    "integrated_summary": "三层配合: 机制→方案→管理"
}
```

呈现:
```markdown
## 🧩 互补完善（拼合后更完整）
**ADHD 运动干预的完整体系**
- 📖 《运动改变大脑》提供神经科学机制
- 📖 《儿童运动处方》提供具体运动方案
- 📖 《儿童发展心理学》提供行为管理
💡 综合: 三层配合——机制→方案→管理
```

#### 冲突辨析层 (conflicts)

```json
{
    "topic": "ADHD 儿童的运动强度",
    "view_a": {"book": "运动改变大脑", "position": "推荐 HIIT"},
    "view_b": {"book": "儿童运动处方", "position": "推荐中等强度"},
    "why_different": "研究对象年龄不同: 10-14 岁 vs 6-10 岁",
    "recommendation": "6-10 岁中等强度，10+ 岁可 HIIT"
}
```

呈现:
```markdown
## ⚠️ 冲突辨析（需按场景选择）
**ADHD 儿童的运动强度**
- 📖 《运动改变大脑》: 推荐 HIIT
- 📖 《儿童运动处方》: 推荐中等强度
🔍 原因: 研究对象年龄不同（10-14 岁 vs 6-10 岁）
💡 场景建议: 6-10 岁中等强度，10+ 岁可 HIIT
```

### 5.3 与自定义知识的协同

| 场景 | 处理 |
|------|------|
| CustomRule 与书籍 CONSENSUS | 标注"专家共识"，强化可信度 |
| CustomRule 与书籍 COMPLEMENTS | 标注"专家补充" |
| CustomRule 与书籍 CONFLICTS | **最高优先级**: 标注"专家纠正"，采信 CustomRule |

## 附录 A: 知识录入流程

### A.1 录入方式

文档上传 + AI 提取。每次最多 **5 份** `.md` 文件。

### A.2 Markdown 格式规范

```markdown
---
source: 来源说明
author: 作者（可选）
---

## 规则

### 规则标题

- **category**: expert_rule
- **priority**: 200

规则正文（Markdown 格式）。

---

### 另一条规则标题

- **category**: clinical_guideline
- **priority**: 150

规则正文。
```

| 字段 | 位置 | 必填 | 说明 |
|------|------|------|------|
| `source` | YAML front matter | ✅ | 文件级来源 |
| `## 规则` | 节标题 | ✅ | 固定标记 |
| `### 标题` | 条目标题 | ✅ | 每条规则的标题 |
| `category` | 属性行 | ❌ | 默认 general |
| `priority` | 属性行 | ❌ | 默认 100 |
| 正文 | 属性行之后 | ✅ | Markdown 正文 |

**关键词和触发模式不需要手写**——AI 自动从标题+正文提取。

### A.3 AI 解析流程

```
上传 .md → 格式校验 → 结构化解析 → LLM 提取 keywords + patterns → 展示审核列表 → 确认入库
```

入库时双写 Neo4j `CustomRule` + MySQL `custom_knowledge_index`。
