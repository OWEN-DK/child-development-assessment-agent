# RAG 检索逻辑优化方案

## 1. 问题诊断
用户反馈在搜索“足球”时，虽然知识库无相关内容，但系统仍返回了结果。经分析，主要原因如下：

1.  **语义漂移 (Semantic Drift)**: 系统使用向量检索 (Vector Search)，即使没有“足球”这个词，embedding 模型也会将其与“运动”、“球类”、“大肌肉活动”等概念关联，产生非零的相似度分数。
2.  **权重配置失衡**: 在 `search_content` 接口中，向量检索权重高达 **0.7**，BM25（关键词匹配）仅 **0.3**。当 BM25 为 0（无关键词匹配）时，只要向量分数达到约 0.43 (0.43 * 0.7 ≈ 0.3)，总分就能超过原定的 0.3 阈值被召回。
3.  **查询重写副作用**: LLM 将“足球”重写为“球类运动、团队协作、大肌肉发展”等泛化词，导致检索范围被不恰当地扩大。

## 2. 优化方案

### 2.1 调整融合策略 (Hybrid Fusion Strategy)
降低向量检索的主导地位，提升精确匹配的权重。

*   **当前**: BM25 (0.3) + Vector (0.7)
*   **调整为**: BM25 (0.5) + Vector (0.5)
*   **新增逻辑 - "无精确匹配惩罚"**:
    如果在 BM25 检索中得分为 0（即知识库中完全不存在该关键词），则对 Vector 检索的得分进行 **降权处理 (例如 x 0.8)** 或 **提高过滤阈值**。这能有效防止系统在只有微弱语义相关性时强行返回结果。

### 2.2 动态阈值机制 (Dynamic Thresholding)
根据匹配质量动态调整阈值，而不是使用固定的 0.3。

*   **基准阈值提升**: 将混合检索的最低阈值从 **0.3** 提升至 **0.5**。
*   **相对分数截断 (Relative Score Cutoff)**:
    *   获取 Top 1 结果的分数 `max_score`。
    *   设定截断比例（如 0.8）。
    *   丢弃所有分数低于 `max_score * 0.8` 的长尾结果。
    *   *效果*: 如果最相关的结果也只有 0.4 分，说明整体都不相关，系统应倾向于返回空结果。

### 2.3 优化查询重写 (Query Rewrite Optimization)
修改 Prompt，限制模型过度联想。

*   **Prompt 修改**: 明确要求“如果查询是具体名词，请保留该名词，不要将其替换为上位词”。
*   **双路检索**: 同时检索 `原始查询` 和 `重写查询`，如果 `原始查询` 的 BM25 无结果，提示用户“未找到精确结果，以下是相关推荐”。

### 2.4 结果重排序 (Reranking - 可选)
如果资源允许，引入轻量级 Cross-Encoder 对 Top 20 结果进行重排序，但这会增加延迟，暂作为备选方案。

## 3. 执行计划

我们将分步实施上述优化：

1.  **Prompt 优化**: 更新 `src/core/prompts.py` 中的 `QUERY_REWRITE_PROMPT`。
2.  **逻辑重构**: 修改 `src/service/rag_service.py` 中的 `search_content` 方法：
    *   调整权重为 0.5/0.5。
    *   实现“无精确匹配惩罚”逻辑。
    *   提升基础阈值。
3.  **验证**: 使用“足球”、“篮球”（假设无）、“前庭觉”（已有）等词进行测试。
