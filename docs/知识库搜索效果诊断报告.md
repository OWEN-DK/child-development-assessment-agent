# 知识库搜索效果诊断报告

## 背景

知识库搜索效果不理想，对 RAG 检索全链路代码进行审查，定位到 **9 个关键问题**，按影响程度排序如下。

用户反馈的具体症状：
1. 相关度评分几乎都一致，看不出区分度
2. 搜索结果只来自一本书，缺乏多源覆盖
3. 年龄过滤实际不需要，反而干扰结果

---

## 问题 1：分数融合体系混乱（影响：严重）

**文件**：[hybrid_retrieval.py](backend/src/core/hybrid_retrieval.py)

三种来源的分数尺度完全不同，被直接线性加权融合：

| 来源 | 分数范围 | 处理方式 |
|------|---------|---------|
| BM25 | 0~30+（原始） | sigmoid 压缩到 [0,1]，再乘权重 |
| 向量检索 | 0.5~1.0（余弦相似度） | 直接乘权重 |
| Cross-Encoder | -10~+10（raw logits） | 直接用于排序，不参与融合 |

**具体缺陷**：

1. **BM25 贡献被系统性压低**（第 222-239 行）
   - BM25 经 sigmoid 后分布集中在 0.5 附近，乘以 0.5 权重后约 0.25
   - 向量分数集中在 0.6~0.8，乘以 0.5 权重后约 0.3~0.4
   - 向量天然占优，BM25 的排序信息被稀释

2. **`_normalize_all_scores` 形同虚设**（第 84 行）
   - 策略 1 的条件 `0.3 <= max_score <= 1.0 and min_score >= 0.1` 覆盖了绝大多数场景
   - 此条件下 `normalized = raw_score`，归一化是 no-op

3. **`_calibrate_vector_score` 引入人为偏差**（第 106-140 行）
   - 高分(≥0.7)保持、中分(0.5-0.7)乘 0.95、低分(<0.5)乘 0.7
   - 这会压低中低分段向量分数，与 BM25 融合后进一步偏向高分向量结果

4. **reranker 的"改善率"指标无意义**（[reranker.py](backend/src/core/reranker.py)）
   - 第 149-153 行比较融合分数（0~1 范围）与 CrossEncoder 原始 logits（-10~+10），尺度不可比

## 问题 2：纯向量检索被双重惩罚（影响：严重）

**文件**：[hybrid_retrieval.py:328-351](backend/src/core/hybrid_retrieval.py#L328-L351)

当 BM25 无结果但向量有结果时，纯向量节点经过两次衰减：

```
最终分数 = cosine_similarity × vector_weight(0.3) × no_match_vector_penalty(0.3)
         ≈ 0.6 × 0.3 × 0.3 = 0.054
```

而搜索阈值 `rag_search_score_threshold_hybrid = 0.25`，导致 **几乎所有纯向量结果被过滤掉**。

另外，第 302 行 `vector_penalty = 1.0 if bm25_nodes else 1.0` 是死代码——无论条件如何结果都是 1.0，说明之前的惩罚逻辑在修改时被错误地"修复"了。

**影响场景**：语义查询（如"自闭症儿童的社交训练方法"）如果 BM25 没有精确关键词命中，向量检索的结果也会被丢弃。

## 问题 3：两套查询分类器互相矛盾（影响：中等）

系统中存在两个独立的查询分类器，使用完全不同的分类逻辑：

| 分类器 | 文件 | 分类依据 |
|--------|------|---------|
| `QueryRouter` | [query_router.py](backend/src/core/query_router.py) | 正则匹配 `有哪些/是什么/怎么` → SIMPLE |
| `PipelineOrchestrator._classify_query` | [orchestrator.py](backend/src/core/pipeline/orchestrator.py) | 检查 `区别/对比/如何/为什么/分析` + `len>20` → COMPLEX |

**具体矛盾**：
- 同一个查询"感觉统合失调有哪些表现"在 `QueryRouter` 中是 SIMPLE（匹配 `有哪些`），但在 `PipelineOrchestrator` 中可能因为长度 >20 被判为 COMPLEX
- 简单流水线**跳过年龄过滤**，意味着像"3岁身高标准"这样的查询返回所有年龄段的结果
- `QueryRouter` 的正则只匹配中文，英文查询永远走 DEFAULT

此外，`QueryRouter` 中第 26-28 行有残留属性定义（`query_type`, `confidence`, `reasoning` 挂在 `QueryType` 枚举上），属于重构遗留的死代码。

## 问题 4：分块质量缺乏保底校验（影响：中等）

**文件**：
- [chunk_chapter.py](backend/src/core/metadata/chunk_chapter.py) — 章节分块
- [chunking_indexing.py:116-124](backend/src/service/document_ingestion/chunking_indexing.py#L116-L124) — 元数据回退默认值

**问题**：
1. 分块只过滤空内容和大小边界，**不检查信息密度**。OCR 质量差的文档会产生碎片块（页眉页脚、版权声明）
2. 碎片块的关键词零散 → BM25 能命中，但内容无意义
3. 元数据提取失败时回退值设为 `target_age_min=0, target_age_max=18, activity_type="Theory"`，等于**对所有年龄段开放**，年龄过滤完全失效
4. EPUB 默认 `chunk_target_size=1024`，PDF 默认 `chunk_size=1536`，尺寸不一致可能导致 EPUB 章节被过度拆分

## 问题 5：YAML 流水线配置与实现不匹配（影响：低-中）

**文件**：
- [rag_pipeline.yaml](backend/config/rag_pipeline.yaml) — 声明 `fusion_mode: "reciprocal_rank"`（RRF）
- [hybrid_retrieval.py](backend/src/core/hybrid_retrieval.py) — 实际使用加权线性求和

YAML 配置了一个不存在的融合算法。`PipelineOrchestrator` 读取了 `fusion_mode` 参数但没有对应的 RRF 实现。

此外 `PipelineOrchestrator` 的 `_classify_query()` 与 `QueryRouter` 使用不同关键词列表，是第三套分类逻辑。

---

## 问题 6：上下文压缩器中文去重不当（影响：低）

**文件**：[context_compressor.py](backend/src/core/context_compressor.py)

使用**单字级别的 Jaccard 相似度**做中文去重（第 144-174 行）：

```python
chars = re.findall(r'[一-龥]', text)
```

- `"感觉统合失调的表现"` 和 `"表现感觉的统合失调"` → Jaccard = 1.0（字符集相同，顺序无关）
- 语义不同的结果会因为字面重叠被误删
- `sklearn.cosine_similarity` 已导入但从未实际使用（死代码）

另外，第 82 行在所有结果低于阈值时返回 `nodes[:5]`，等于**把判定为不相关的结果强制塞回**，可能误导下游 LLM。

## 建议修复优先级

### 第一优先级（运行时崩溃或核心功能失效）

1. **修复 Pipeline 重排序参数签名**（问题 8）— `RerankingStep` 传入不存在的 `candidates=` 和 `top_k=` 参数，导致重排序在 pipeline 模式下永远不生效（TypeError 被 except 吞掉）。这是搜索质量差的直接原因之一。
2. **修复结果融合 limit 参数**（问题 7）— `rag_service.py` 传 `limit=` 给 `fuse()` 但方法签名不支持，复杂查询触发 TypeError。
3. **修复 PageIndex 增强步骤**（问题 9）— `pageindex_enhancement.py` 调用不存在的 `fuse_pageindex()` 方法。
4. **重写分数融合逻辑**（问题 1）— 统一尺度，实现真正的 Reciprocal Rank Fusion。

### 第二优先级（静默质量劣化）

5. **修复纯向量双重惩罚**（问题 2）— 消除死代码，修正惩罚逻辑。向量独有三重惩罚（问题 17）也需一并修复。
6. **重排序 logits 归一化**（问题 12）— 对 CrossEncoder 输出施加 sigmoid，让下游阈值有意义。
7. **修复 PageIndex score/confidence 字段映射**（问题 11）— 在 `_parse_response` 或融合器中统一为 `score`。
8. **修复同义词扩展双 system prompt**（问题 10）— 第二次 `get_prompt("synonym_expansion")` 应使用独立的 system prompt key。
9. **统一查询分类器**（问题 3 + 13）— 合并两套分类器为单一实现，修复 `QueryType` 枚举冲突。
10. **Pipeline 路径补齐缓存和 A/B 测试**（问题 14）— `_retrieve_via_pipeline` 需支持 `user_id` 和缓存。
11. **查询 Embedding 添加重试**（问题 15）— 单次查询 embedding 应复用 batch 的 3 次重试逻辑。

### 第三优先级（设计缺陷）

12. **增加分块质量校验**（问题 4）— 过滤碎片块，修正元数据回退值。
13. **同步 YAML 配置与实现**（问题 5）— 要么实现 RRF，要么修改 YAML 声明。
14. **替换中文去重算法**（问题 6）— 使用 jieba 分词 + 词级 Jaccard。
15. **修复跨源去重 hash 归一化**（问题 16）— 统一两源内容的 hash 计算方式。
16. **修复分数校准边界不连续**（问题 18）— 消除 0.7 处的阶跃。
17. **年龄过滤统一阶段化容忍度**（问题 19）— `build_metadata_filters` 应调用 `DynamicAgeFilter` 的阶段配置。
18. **放宽同义词验证逻辑**（问题 20）— 改为词汇级别的覆盖度检查。
19. **修复分层生成 fallback**（问题 21）— 将 `layered_config` 作为参数传入。
